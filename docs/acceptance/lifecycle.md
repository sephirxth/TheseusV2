# 启停：验收规格 U1–U6

> 这份文档回答：**怎么知道 [`docs/requirements/lifecycle.md`](../requirements/lifecycle.md) 里那六条体验真的兑现了。**
>
> 它不是设计文档那种"每个手段怎么验"。**层次不同：**
> **手段级的测试问「这个零件对不对」；这一份问「这个人的日子过好了没」。**
>
> VISION 写着「tests 应按照用户用例组织」——**这份文档就是那条要求的兑现物。**

---

## 四条纪律

**一、只从需求推。** 每条断言必须能指回需求文档里的某一句"我应该体验到"。
**不许看设计文档，不许看代码**——否则就成了用代码验证代码。

**二、只走用户看得见的那道门。** 验收测试只准用调用方能用的东西（那三个动作 + 观察真实系统：进程、文件、系统自己的查询手段）。
**不许 import 内部模块。** 要是一条断言非得摸内部才能验，说明这个体验根本没被交付到外面。

**三、断言"人的处境"，不是"机制的状态"。**
反例：「锁被正确释放了」——那是机制。
正例：「我没有被要求按任何顺序做事」——那是处境。

**四、不是每条都得是代码。** 有些体验只能靠扫文档验（见 U2-4）。**那也算验收，而且往往是最要紧的那条。**

---

## U1 · 我要把系统跑起来

```
给定   一份声明：三个部件，其中 B 依赖 A，C 依赖 B
当     我做那个"让它跑起来"的动作
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U1-1** | 该跑的都在跑 | 三个部件的进程都真实存在 | "该跑的都跑起来了" |
| **U1-2** | 顺序对 | A 的启动时刻早于 B，B 早于 C | "顺序对" |
| **U1-3** | **连做三次，还是那些进程** | **数进程，不看动作的返回值**。三次之后进程数与一次之后相同，且是同一批进程（没有被重启过） | "手滑连做三次，还是那些进程，不会起出重复的" |
| **U1-4** | 只起一个，它依赖的跟着来 | 只点名 C，结果 A 和 B 也在跑 | "起一个，连它依赖的一起带起来" |
| **U1-5** | **我不需要知道谁依赖谁** | 调用方只给了一个名字，**没有以任何形式提供顺序**，结果仍然正确 | "我不需要知道谁依赖谁" |

## U2 · 我要把系统停干净

```
给定   系统在跑，其中一个部件会 fork 出孙进程
当     我做那个"停"的动作
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U2-1** | **它说完成的那一刻，就是真停了** | **在动作返回的那一瞬间断言进程数为 0。不许 sleep 之后再查** | "不是「它说它停了」" |
| **U2-2** | 孙进程也没了 | 那个 fork 出来的孙进程同样不存在 | "不会留下什么在后台偷偷跑" |
| **U2-3** | **痕迹不再增长** | 记下返回那一刻的痕迹大小，等一段时间再看，**必须一模一样** | "是它留下的痕迹不再增长了" |
| **U2-4** | **我没有被要求按任何顺序做事** | **扫全部文档：把每一句"先…再…"找出来。只要还有一句是写给操作者的，本条不通过** | "我不需要记住任何顺序" |

> **U2-4 是这份规格里最重要的一条，而且它不是代码测试。**
> 它对应 2026-08-05 那次事故：必须先关定时器再停服务，**顺序错了两分钟后系统自己回来，而那条顺序只存在于操作者脑子里。**
> **一条只存在于人脑子里的规矩，代码测试永远抓不到。**

## U3 · 我要知道现在什么在跑

```
给定   系统里既有在跑的部件，也有没起来的
当     我问"现在什么在跑"
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U3-1** | **说在跑，就真在跑** | 它报"在跑"的每一个，去真实系统里核，必须确实有活进程 | "说在跑就是真在跑" |
| **U3-2** | **说停了，就真停了** | 它报"停了"的每一个，真实系统里必须一个进程都没有 | "不会出现「它说停了、其实还在跑」" |
| **U3-3** | **还在启动中的，不许说成在跑** | 造一个启动很慢、**并且声明了"什么算它起来了"**的部件；在那句话被满足之前问，答案不许是"在跑"，满足之后才是 | "不会出现「它说跑着、其实还在启动中」" |

> **U3-3 是这份规格第一次跑就报红的那一条**，也是这次工作全部价值所在。
> **原有 45 条里 `I4: activating is NOT running` 是绿的**——它拿"启动中"这个字符串喂给翻译函数，验的是零件对不对。
> 而实测：对一个 5 秒后才干活的部件每 5 毫秒采一次状态，**152 次采样里"启动中"一次都没出现**，状态直接从"停着"跳到"在跑"。
> **零件全绿，体验没交到人手上。**
>
> **⚠ 断言措辞改过一次，得说清楚这不是放宽**：原来的写法是"造一个启动很慢的部件"，没有"声明了什么算起来"这一句。
> 但**没有任何系统能猜出一个程序什么时候准备好了**——没有那句声明，这条断言要求的是不可能的事。
> 补上声明这个位置，是把**本来就该在声明里的东西**补上（需求 U4 已同步改成"说清它叫什么、依赖谁、怎么起，**以及什么算它起来了**"）。
> **真正的分寸线在这里**：声明了却不尊重它 → 红；**没声明就报"进程在跑"** → 那是诚实，不是撒谎。
| **U3-4** | **问不出来的时候，不许说"停了"** | 让它问不到底层系统，答案必须是"我问不到"，**不许降级成"什么都没跑"** | "说不知道就是真不知道" |

> **U3-4 对应旧系统最贵的那个 bug**：把"问不出来"一律当成"已经结束"，
> 于是一个还在干活的执行器被判了死，系统转头又派一个——**同一件活两个进程在做。**

## U4 · 我要加一个新部件

```
给定   一份已有的声明
当     我在声明里加一行
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U4-1** | **只动声明这一处，新部件就被纳管了** | **加完之后统计：除了声明那个文件，没有任何别的文件被改过。** 新部件能起、能停、能被问到 | "写一行声明，它就被纳管了。不用改启停的代码，不用手写什么配置文件，不用去某个安装脚本里补一行" |
| **U4-2** | 依赖绕了个圈 → 当场报错并点名那条链 | 错误信息里必须出现构成环的那几个名字 | "依赖绕了个圈…应该被拦下来" |
| **U4-3** | 依赖的东西不存在 → 当场报错并点名 | 错误信息里必须出现那个不存在的名字 | "依赖的东西根本不存在" |
| **U4-4** | **在动手做任何事之前拦下** | 出错时，**磁盘上一个文件都没被生成，一个进程都没被启动** | "**在动手做任何事之前**就被拦下来" |

## U5 · 我要把 Theseus 搬到另一台机器

```
给定   一台什么都没装的机器（模拟成：把这份声明产生的东西全部清掉）
当     我把仓库拷过去，做那个"让它跑起来"的动作
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U5-1** | 完全恢复 | **按名字逐个列出**这份声明产生的每一个装到系统里的文件，删光；做一次启动动作，一切照旧 | "把仓库拷过去，做一个动作，就好了" |
| **U5-2** | **没有单独的安装步骤** | 扫仓库与文档：**不存在任何一个"必须先跑一次"的安装脚本**；也不存在"装完之后还要手动做一件事"的说明 | "**因为根本没有单独的安装步骤**" |
| **U5-3** | 没有东西被落在系统里 | 装到系统里的每一样，都能从仓库里的声明推出来；**反过来，系统里不该有任何一样是声明推不出来的** | "不会出现「忘了还有个东西装在系统里」" |

> ⚠ **U5-1 必须按名字逐个删，绝不可用通配。**
> 通配会连旧系统那几个同前缀的东西一起删掉——**这条验法的第一版就是这么写的，是一条真写下过的危险指令。**

## U6 · 出问题时我要能查

```
给定   系统在跑
当     我去查"现在应该有什么在跑"
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U6-1** | 装着、但声明里没有的 → 被点名 | 手工塞一个进去，必须被主动报出来 | "不存在「还有个东西在跑，但不在清单上」" |
| **U6-2** | 声明了、但没装的 → 被点名 | 手工删掉一个该装的，必须被主动报出来 | "也不存在「清单上有，实际没装」" |
| **U6-3** | **在跑、但盘上没有它的文件的 → 也要被点名** | 造一个盘上无文件却在运行的，**它不许从列表里消失** | "旧系统里有个服务…停掉之后从列表里凭空消失了" |
| **U6-4** | **不只能用 Theseus 自己的工具** | 每个部件都要能被底层系统自带的查询手段直接查到、直接跟日志 | "不该只能用 Theseus 自己的工具" |
| **U6-5** | **主动报，不是等我撞见** | 上面三种对不上，**在正常的那一问里就要出现**，不需要额外加参数、额外敲一条别的 | "都应该被主动报出来，而不是等我某天偶然撞见" |

## 这份规格自己的验收

跑完之后要能回答一句话：**"U1 到 U6，哪几条绿了。"**

现在回答不了——45 条测试全按手段编号命名（`I1` / `O2a` / `E4` / `I4` …），
**能回答"I4 过了吗"，回答不了"U3 过了吗"。而人从来不问 I4。**

**预期**：多数会绿（代码是照着同一批需求写的）。
**真正有价值的是红的那几条**——它们说明：**代码通过了 45 条零件检查，却没把某个体验交到人手上。**
