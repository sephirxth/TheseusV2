# 痕迹：验收规格 U7–U14

> 这份文档回答：**怎么知道 [`docs/requirements/trace.md`](../requirements/trace.md) 里那八条体验真的兑现了。**
>
> **和启停那份最大的不同：那边先有代码、验收去审计；这边还没有代码、验收去塑形。**
> 所以每条断言都要在**不知道实现长什么样**的前提下说得清。
> 断言里出现任何实现细节（用什么存、几个字段、什么格式），都是写错了。

---

## 四条纪律（沿用 [`lifecycle.md`](./lifecycle.md)）

**一、只从需求推。** 不看设计文档，不看代码。
**二、只走用户看得见的那道门。** 不许摸内部。要是一条断言非摸内部才能验，说明这个体验没被交付到外面。
**三、断言「人的处境」，不是「机制的状态」。**
**四、不是每条都得是代码。** 有些只能扫文档、或者拿真实旧数据量。

**这一份多一条纪律：**

**五、不许把实现写进断言。** 反例：「那条记录的 `cause` 字段指向上一条」。
正例：**「我问它为什么，它给的每一步都指得出上一步，中途不断」**。
前者一换实现就作废，后者永远成立。

---

## 现在就能跑的三条（不依赖新代码）

有三条断言**只依赖旧账本，今天就能量**。**先量出现状，再写代码**——不然代码写完了没有对照，说不清是变好了还是本来就那样。

**三条都量完了（2026-08-10）。数字如下，其中一条把规格自己改了。**

| | 量什么 | 量出来是多少 |
|---|---|---|
| **U9-3** | 默认视图里"值得一看"的占比 | 8 月 12862 条里，**值得一看的只有 194 条 = 1.51%**，例行 98.5%。**目标：默认只给那 1.5% 上下**<br>（这个数错过一次：先报 412 条 = 3.2%，是分项与小计相加对不上导致的虚高。2026-08-10 重算并复核） |
| **U13-2** | 旧文档里指向痕迹的锚还指不指得中 | 表面 99.9%，**但这个数是假的**——见下 |
| **U14-3** | Theseus 这份是不是最全的 | **红的。62 条里缺 14 条**，而且**缺的 14 条里 11 条是"用户偏好"——21 条偏好只记住了 10 条** |

### U9-3 的口径必须写死，不许留解释空间

例行 = 这五类：**时钟到点、触发器自己的记账、定期搬运对话、主动思考周期开始、主动思考的结论是"没事可做"**。

**其中一条是判断，得挑明**：定期搬运对话（`ingest.transcripts`）**不是空心跳**——1471 条**每一条都真的搬了文件**。仍归例行，理由是**机械搬运、无语义**。

**为什么必须写死**：这一条归哪边，占比从 **3.2% 跳到 15.4%**，差近五倍。**一个能被口径左右五倍的指标，不写死就等于没有指标。**

### U13-2：99.9% 是个假绿灯，基线已改

原本要用的基线是"2465 份文档、3626 个锚、命中 99.9%"。**核实后作废。**

**前 5 个锚占了 2300 次出现 = 63.4%**，全部来自 2026-06-10 同一次导入，分别盖在 500 / 500 / 500 / 500 / 300 份文档上。它们长这样：

```
{"type":"ingest.roam","payload":{"batch":4,"batches":5,"batch_pages":500}}
```

**每份文档被盖上"我属于第几批导入"的戳。锚能解析，但它不指向这份文档的任何痕迹**——它是为了满足"不带锚就拒写"那条规矩盖的**合规章**。

**去掉这 5 个之后：165 份文档、699 个锚**——文档数掉到十五分之一。

**所以 U13-2 的基线改成 165 份 / 699 个锚。** 用原来那组，"命中率"会永远绿着，**测不出任何退化**。

> 只有 1 个锚指不中：`2026-06-11#evt-20260611032206974000-2f2bc197`，出现在 `L2_projection/intent_tree/tree.md`。
> 缺的时间点卡在同日两条真事件中间——**像是事件写失败，但引用已经写进文档了**。

## U7 · 我要能查「刚才那件事为什么发生」

```
给定   系统里发生了一串有前因后果的事
当     我指着最后那件事问"它为什么会发生"
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U7-1** | **每一步都指得出它的上一步** | 顺着答案往回走，每一跳都能落到一条真实存在的记录上 | "每一步都指得出它的上一步" |
| **U7-2a** | **一直查到一个我认得的起点** | 走到头那一条必须是三种之一：**我说的一句话 / 一个到点的时刻 / 一条从外面进来的消息**。**经这道门写的痕迹，没有上一步就必须当场三选一** | "一直查到一个我认得的起点" |
| **U7-2b** | **停在不认识的东西上，要明说** | 对**不是经这道门进来的**痕迹，走到头是个认不出的起点时**必须明说**，不许硬塞进三种里的一种 | 同上 |
| **U7-3a** | **中途不许断** | 写一条指向不存在记录的痕迹，**当场被拒，而且什么都没留下**。**断链是造不出来，不是没碰上** | "中途不许断" |
| **U7-3b** | **断了要明说** | 对**不是经这道门进来的**痕迹，答案必须明说"这里断了"，**不许猜一个接上去** | 同上 |

> **U7-2 和 U7-3 各自劈成两半（2026-08-10），断言没改，改的是验法。**
>
> 原来的验法写死了一个动作：**故意抽掉中间一跳**。写规格时这个动作是成立的——旧账本里就有 0.2% 指向不存在的事件。
> 但在新系统里**经这道门断链造不出来**（上一步必须已存在、门里没有删除动作、清理只折叠没人指着的）。想抽掉一跳，只能绕到门后面直接改库。
>
> **而那样验出来的绿说明不了运行中的系统——它验的是一个这个系统到达不了的处境。**
> 这跟纪律二是同一件事：**一条验法要是必须绕过门才能执行，它就不属于这一轮。**
>
> **但它不是永远错。** 旧账本那 0.2% 不是经这道门写的——**U13 一进来，b 那半立刻就有第一个真场景。**
> 代码里那两个"断了"和"认不出"的分支现在跑不到，**留着不是死代码，是给 U13 的。**
| **U7-4** | **不许编** | 抽掉一跳之后，**它不许猜一个接上去**。宁可说"到这儿就没了"，也不许给出一个看起来连着、其实是猜的链子 | "也不需要我猜。不会出现「这儿应该是那个东西触发的吧」这种句子" |

> **U7-4 是这条里最要紧的。** 需求文档里那条更正记着：真实账本的链子其实**大体是连的**（真断的只有 0.2%），
> **所以 U7 的风险不在"断"，在"为了不断而编"。** 一条编出来的链子比断了更贵——**断了你知道自己不知道，编了你以为自己知道。**

## U8 · 我要能查「这件事为什么没发生」

```
给定   我提了一个要求，而系统决定不去做它
当     我问"我那个要求后来怎么了"
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U8-1** | **没做的事也留痕** | 四种都要能查到：**决定不做 / 决定推迟 / 把两件当成一件 / 把请求丢掉** | "没做的事，和做了的事一样留痕" |
| **U8-2** | **还要留下它当时凭什么这么定** | 查出来的不只是"它没做"，**还有它当时依据的是什么** | "还要留下它当时凭什么这么定" |
| **U8-3** | **复现那次真事故** | 提两个**相似但不同**的要求（例如两个版本号只差一位）。**无论系统把它们当成一件还是两件，我都必须查得出第二个发生了什么**——不许查不到 | 那次 numpy 2.1.0 / 2.2.0 被静默吞掉 |
| **U8-4** | **静默是不合格的** | 上面那种情形下，如果第二个要求在痕迹里**完全不存在**，本条直接不通过。**"没记录"不是一种合格的答案** | "一声不吭" |
| **U8-5** | **「没做」有几种，我分得清是哪一种** | 五种情形各造一次（**不做 / 推迟 / 并进了另一件 / 被丢掉 / 不知道做没做**），**同一句问法问五遍，得到五个我一眼分得清的答案**。两种答案要是听起来一样，本条不通过 | "没做的事，和做了的事一样留痕" |
| **U8-6** | **并进另一件时，三样东西缺一不可** | 答案里必须同时有：**留下的是哪一个、被并掉的是哪一个、当时凭什么判成同一件**。缺一样不通过 | "还要留下它当时凭什么这么定" |
| **U8-7** | **「不知道做没做」不许被说成「没做」** | 让它转一笔账，**中途拔电**。之后我问这笔账，答案必须是**"不知道转没转"**——不许说"没转"，不许说"转了"，**也不许它自己悄悄再转一遍**。要么让我确认，要么先去查账户真实余额 | U7 "也不需要我猜" + U8 "一声不吭" |
| **U8-8** | **我不需要事先知道有东西被吞了** | 重做 U8-3 那个场景，但**这次不许我知道有第二个**。我只问一句"最近有哪些要求，既没被办、也没有一句话说明它为什么没被办"，**第二个必须自己出现在这个列表里** | "它最后是被人去读代码读出来的，不是被查出来的" |
| **U8-9** | **没人问的时候，也得有人喊** | 造一条这样的要求，然后**什么都不做**。过一段时间，**报警必须自己出现**，不是等我想起来去问。<br>⚠ **同时验反面：一个还在排队、只是没轮到的要求被报成失踪，本条同样不通过** | "一声不吭" |
| **U8-10** | **说不清凭什么的「不做」，根本写不进去** | 我让它记下"这件事我不做了"，**但不说为什么**——它必须**当场不让我记**，而不是记下来再说。试完去看，**痕迹里什么都没留下** | "还要留下它当时凭什么这么定" |
| **U8-11** | **说不清并掉了谁的「合并」，同样写不进去** | 我让它记下"这两件是同一件"，**但不点名被并掉的是哪一个**——当场拒 | 那次 numpy 2.1.0 / 2.2.0 |
| **U8-12** | **每一种「没做」，都说得出它写进来之前查什么** | 扫一遍所有"没做"的种类：**每一种要么写着"写进来之前查这个"，要么写着"什么都不查，因为……"。空着的一律不通过** | —— |

> **U8-3 是整份规格里唯一一条直接复现真实事故的。** 那次的实测数字：
> numpy 2.1.0 / 2.2.0 像 95.5%、PR #412 / #418 像 94.1%、转账 500 元 / 800 元像 90.9%——**全被吞掉，一声不吭。**
> 它最后是被人去读代码读出来的，不是被查出来的。**这条断言就是为了让下次能被查出来。**
>
> **但 U8-3 有个洞，U8-8 才是补它的那条（2026-08-16）。**
> **U8-3 假设我知道该去问 numpy 2.2.0。当年真实的处境是：没有任何人知道有东西被吞了。**
> 所以 U8-3 就算全绿，也说明不了那次事故会被发现——**它只说明"我指着问的时候答得上"。**
> **U8-8 验的是"我没指，它自己冒出来"。这两条不能互相顶替。**
>
> **U8-8 和 U8-9 是一对，形状和 U14-3 / U14-4 完全一样**：前者是"我问得到"，后者是"没人问也有人喊"。
> **不许用 U8-8 的绿去掩盖 U8-9 的红。** 当年那件事的真正代价不在"查不到"，在**没有任何东西喊过一声**。
>
> **U8-9 为什么必须连反面一起验**：这份规格后面写过，**一条会冤枉人的检验，和一条不会说"不"的检验一样坏**——
> 它一响，人先怀疑的是检验而不是系统；几次之后就没人当回事了。
> **"多久没有后继才算失踪"这个时限定错，这条报警就会变成那种没人看的红灯。**

> **U8-7 的出处要挑明，因为它比需求原文多走了一步。**
> 需求 U8 列的是四种（决定不做 / 决定推迟 / 把两件当成一件 / 把请求丢掉），**没有第五种"不知道做没做"。**
>
> 这条是从**"不许编"**推出来的：**把"不知道"报成"没做"就是编**，而且是最贵的一种编——
> 断了你知道自己不知道，编了你以为自己知道（U7-4 那句原话）。
> 报成"没做"更糟一层：**它给了一个确定的假答案，而人会拿着这个假答案去做下一步决定**——比如再转一次那 500 块。
>
> **要是觉得这一步推得太远，该做的是补需求，不是删这条断言。**

> **U8-12 指不回需求里的任何一句，因为它不是一条体验，是一条制度。留着它的理由：**
> 它**不检查那些校验对不对**，只检查**有没有人回答过"这里该查什么"这个问题**。
> **一个种类写着"什么都不查，因为它只是一条纯记录"，和一个种类压根没人想过——在文件里长得完全不一样。**
>
> **它按纪律四走"扫文档"这条路**，不是跑代码。这也是它现在的软肋：**扫的是人写的字，不是系统的行为。**

> **U8-5 那句"两种答案要是听起来一样，本条不通过"是认真的，不是修辞。**
> 分类要是分了却分不出来，读的人拿到的还是"没成功"这一个笼统答案——**那还不如不分**，
> 因为它多花了写的人的力气，却没给读的人多一个字。

## U9 · 我要一眼看见有意义的事，不被心跳淹掉

```
给定   痕迹里既有例行公事，也有值得一看的事
当     我说"看看最近都发生了什么"
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U9-1** | **默认给我的，基本没有例行公事** | 默认结果里例行的占比，必须低到我不会被它们淹掉 | "翻开就是「发生了什么」，不是一屏又一屏每两分钟一条的自动心跳" |
| **U9-2** | **我要全部时，能拿到全部** | 明说要看心跳，它们就出现 | "也要能要求「把心跳也给我看」，但那不该是默认" |
| **U9-3** | **拿真实旧数据量一遍** | 把旧账本 8 月那 **12862** 条喂进去，**默认视图应落在 1.5% 上下**（实测值得一看的 194 条）。**要是打完标发现"值得一看"的还有一半，是规则定错了，不是数据的问题** | "98.5% 是自动产生的" |

## U10 · 系统自己也读这份痕迹

```
给定   系统写了一段关于它自己的总结（反思 / 自我认知 / 改进结论）
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U10-1** | **每条结论都指得回具体的痕迹** | 随便挑一条结论，它依据的那几条记录必须都在，而且**说得通** | "凭的是这份痕迹，不是凭一份人手写的自我介绍" |
| **U10-2** | **指不回去的，根本不该被写下来** | 试着写一段**没有任何依据**的自我总结——**必须被拒绝**，不是被接受然后打个标记 | "不会出现「文档里写它这么干」和「它实际那么干」是两回事" |
| **U10-3** | **我看的和它看的是同一份** | 同一个问题，我去问、和它自己去问，**答案必须一致** | "我对它的了解，和它对自己的了解，来自同一份东西" |

| **U10-4** | **依据不许是合规章** | **写的时候当场拒：一条结论的依据不能全是例行公事。** 顺着依据回去看到的必须是"这条结论从哪来"，不许是"这份文档属于第几批导入" | "凭的是这份痕迹" |

> **U10-4 的验法在实现时被改过一次，理由比原来的强，记下来（2026-08-10）。**
> 原来写的是**事后抽样**。执行者改成**写时当场拒**，理由是：
> **"一条只在事后抽样的检验，会被'没人去抽'满足"——正是这份规格自己在讲的那个病。**
>
> **新规则拦得住那次真事故**：2026-06-10 那 2300 个合规章指的是 `ingest.roam`，属于例行；
> 一条结论要是依据全是这种，当场被拒。
> 为此实现里把"例行"的判定从只认一个类型名推广成认 `ingest.` 前缀——**只认一个名字，那次事故就认不出来**。
>
> **它拦不住什么，也说清楚**：一个指向**非例行**事件的合规章仍然能过（比如给每份文档都盖同一条任务完成）。
> 那一半只能靠人去看，**而"没人去看"正是它会失效的方式**。见 ★11。
>
> **代价**：一条真正只该拿例行当依据的结论（例如"心跳太密了"）会被拒，写的人得再加一条非例行的依据。
> **接受这个代价的理由：拒是当场看得见的，盖章是几个月后才发现的。**

> **U10-2 是这条唯一硬得起来的地方。** 这条用例本来最虚——它没有一个"我去干什么"的动作。
> **但"写不进去"是可以当场验的**：拒绝一次没有依据的自我描述，比事后发现它错了要早得多。
> 旧系统那道"不带锚就拒写"的规矩，正是这条的现成形状。
>
> **⚠ U10-4 是 2026-08-10 量基线时撞出来的，而且它是这份规格里最重要的一条警告。**
> 旧系统**确实有**"不带锚就拒写"这条规矩。结果是：一次导入给 2300 份文档各盖了一个"我属于第 N 批"的锚——
> **规矩被满足了，满足得毫无意义。** 那 5 个锚占了全部锚的 **63.4%**。
>
> **教训不是"这条规矩没用"，是"一条只检查形式的规矩，会被形式满足"。**
> 所以 U10-2（不带依据不许写）必须配 U10-4（依据得真的是依据），**单有前一条，等于没有。**

## U11 · 我要它一年后还能用

```
给定   痕迹已经很大了
当     我像平常一样去问一件事
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U11-1** | **量涨了，查一条的代价不跟着涨** | 把量放大一个数量级，**问同一个问题的耗时不许成比例增长** | "翻它的代价不能跟着一直涨" |
| **U11-2** | **老东西不消失** | 老的例行事件即使不再逐条保留，**"那一天发生过多少次"仍然答得出来** | "痕迹会一直长，这没办法" |
| **U11-3** | **清理不许制造断链** | 做完清理之后**重跑一遍 U7 的全部断言**，必须还是绿的 | U7 "中途不许断" |
| **U11-4** | **我们自己不许犯这个病** | **扫仓库与运行痕迹：不存在任何"只增不删"的东西**（含测试留下的临时物） | 2026-08-09 实测：测试在 `/tmp` 留了 1423 个残留、6.4M，**最老的是开工那天** |

> **U11-4 是从一次现场事故来的。** 我们一边写着"只增不删是病"，一边自己的测试每跑一次多留一份。
> **一条需求要是连自己家里都没守住，它就还不是一条需求，只是一句话。**

## U12 · 我不需要谁「记得」去留痕

```
给定   一件事发生了，而没有任何人、任何 agent 做过"记一笔"这个额外动作
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U12-1** | **部件干的事，自动就在** | 一个部件输出了东西，**没人做任何额外动作**，痕迹里就有 | "事情发生了，痕迹就在" |
| **U12-2** | **对话自动就在** | 一次对话发生了，同上 | "不靠哪个人、哪个 agent 记得多敲一条命令" |
| **U12-3** | **一个什么都不主动记的 agent，事后仍能查到它干了什么** | 故意让它一条都不主动记。**"它做过这件事"必须仍然查得到** | 旧系统：负责回复的副本经常做完回复、忘了留痕，**对用户发生了，对系统从没发生过** |
| **U12-4** | **诚实的边界要被明示** | 要是某一类痕迹仍然依赖谁记得，**这件事必须写在明处**（缺口表里），不许含糊过去 | — |

> **U12-3 和 U12-4 是一对。** U12-3 验的是"粗的兜住了"；U12-4 承认"细的还漏"。
> **不许用 U12-3 的绿去掩盖 U12-4 的红。**

## U13 · 旧的记忆整个接进来

```
给定   旧的那批记忆已经接进来了
当     我问一件很早以前发生的事
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U13-1** | **同一个问法，不分新旧** | 问 6 月的事和问今天的事，**用完全一样的方式**，都得到答案。**我不需要先想它在分界线哪一边** | "不用先想它发生在新旧分界线的哪一边" |
| **U13-2** | **旧文档里的引用一条都不许失效** | **基线：165 份文档、699 个锚**（已剔除那 5 个批量合规章——见开头）。接进来之后**逐条核，必须全中**。<br>⚠ **不许拿含批量章的那组当分母**，那会让这个指标永远绿着 | "旧 memory 不是「归档」…它就是这个系统记忆的一部分" |
| **U13-3** | **限制必须当场说出来，不是写在文档里** | 查一件分界线之前的事，**如果它的链子只到"时钟到点"这种答不了"为什么"的起点，答案里必须说出这一点**——不许把它当成一个有意义的答案交给我 | "**不能让它看起来像做到了**" |

> **U13-3 是这份规格里最容易被做漏的一条。**
> 一条"技术上完整、实际上没回答问题"的链子，**长得和一条好链子一模一样**。
> **限制写在文档里没用——它必须在我问的那一刻出现在答案里。**

## U14 · 换个 agent、换个会话，它还记得

```
给定   我先跟一个 agent 聊过一件事
当     我换一个 agent、或者开一个新会话
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U14-1** | **换 agent 接得上** | 在 A 那儿说过的，B 查得到 | "我在这台机器上跟任何一个 agent 说过的话，都进同一份痕迹" |
| **U14-2** | **我不用重讲一遍** | 新会话开场，我不需要把背景重述一次 | "新的那个接得上，我不用重讲一遍" |
| **U14-3** | **Theseus 这份必须是最全的** | 拿别的 agent 自己那份记忆做对照，**Theseus 这边必须是超集**。**并存可以，缺东西不行**。<br>⚠ **判"有"的时候必须排除两种假命中**：① **命中的是对照源自己的副本**（那份索引被整份读进过某次对话，于是它在痕迹里留了一份拷贝）；② **命中的只是标题或文件名，正文不在**。**照镜子不算记得** | "问题是 Theseus 这份必须是最全的那一份" |
| **U14-4** | **不全的时候要有人喊** | 故意让 Theseus 这份缺一条，**必须被发现并报出来**，不许静静缺着 | "也没有任何东西会在它变得不全时喊一声" |
| **U14-5** | **我不需要记得上次是跟谁说的** | 我只说"我上次讲过的那个事"，不给 agent 名字、不给会话编号，它得找得到 | "我也不需要记得「上次是跟谁说的」" |

> **U14-3 今天就是红的，而且量出来了**（2026-08-10）：别的 agent 那份索引 62 条，**Theseus 这边缺 14 条**（先报 16，搜过对话档案后更正为 14——有两条确实记着，其中一条还是当时的实际决策依据）。

> **⚠ 这个数差点是假的。** 那 62 条里，**有 45 条（73%）的名字，只在一个对话文件里就能搜到**——因为**那份索引本身被整份读进过一次会话**，于是它在痕迹里留了一份拷贝。
> 要是把 U14-3 实现成"去痕迹里 grep 索引里的条目"，**它会当场报出 73% 的完整度，而真实数字是 77%（48/62）里还得再打折**。
> **照镜子不算记得。**
>

>

> |---|---|
> | **项目事实** | Theseus 这边**更全**，有些还**比那份索引更新**（例如 canvas-first 的定义在这边被修正过） |

> **也就是说：这个系统记得住"发生过什么"，记不住"你是怎么想的"。**

>
> **U14-4 比 U14-3 更要紧**——缺东西难免，**没人喊才是病**。而现在的情况正是：缺了 62% 的偏好，**没有任何东西喊过一声**。

## 一族断言：「写不进去」

这份规格里有五条长得一样，散在 U7 / U8 / U10 三条用例下面。**它们是同一族，标准也该是同一条：**

| | 我干了什么 | 必须发生什么 |
|---|---|---|
| **U7-3a** | 写一条指向不存在记录的痕迹 | 当场被拒，**而且什么都没留下** |
| **U8-10** | 记一条"这件事我不做了"，但不说为什么 | 同上 |
| **U8-11** | 记一条"这两件是同一件"，但不点名并掉了谁 | 同上 |
| **U10-2** | 写一段没有任何依据的自我总结 | 同上 |
| **U10-4** | 写一段依据全是例行公事的自我总结 | 同上 |

**这一族只能写成"我干了 X，当场被拒，而且什么都没留下"**——不能写成"某个函数返回了什么"，
也不能写成"事后抽样查不到这种记录"。**"当场"和"什么都没留下"，两半都不能少：**

- **当场**：U10-4 的验法就是被这个理由改过的。原来写的是事后抽样，改成写时当场拒，理由是
  **"一条只在事后抽样的检验，会被'没人去抽'满足"**。同一条理由适用于这一族全部五条。
- **什么都没留下**：被拒之后表里要是躺着半条，那不是拒，是"记下来再报错"。**这两者在事后长得一模一样。**

**这一族有个共同的软肋，得写在明处**：★13 记过——U7-3a 的绿压在两道护栏的合取上，
**去掉任一条它仍然是绿的**。这一族每一条都有这个毛病：**它们只证明"这条路走不通"，
不证明"哪一道栏杆拦住的"。** 拆开验要两个写入进程一起上，单进程测试演不出来。

**还有一件这一族做不到的事，也写在明处**：它们全都在管**"写进来的东西对不对"**，
**没有一条能管"该写的东西没写"**——**缺席在写的那一刻并不存在，没有哪一次写入可以被拦。**
那一半归 U8-8 / U8-9（事后扫 + 主动喊）。**这两半不能互相顶替，也不能互相掩盖。**

## 为什么这里没有「不丢、不重」的断言

需求文档说过：这件事**不是"一个人要干的事"**，它是上面八条全部成立的**前提**。所以它不占用例的位置，归技术实现那边当硬约束。

**但要说清一件事**：它一旦破了，**U7 到 U14 会同时悄悄变成错的，而表面上一切正常**。

**所以对它的检验必须放在机制层，而且必须是那种"坏了会立刻喊"的检验**——不能是"跑一遍看起来对"。
2026-08-05 我宣布旧系统已停，用的证据是"记录不再增长"，**那条证据在"真停了"和"我看的窗口太短"两种情况下都成立**——而当时是后者。

**这类检验的标准只有一个：它什么时候会说「不」。说不出来的，就不是检验。**

## 一条贯穿这份规格的病：检验被形式满足

量基线那一天（2026-08-10）**一天之内撞见两次同一个病**，形态完全不同：

| 检验 | 本来要保证什么 | 被什么满足了 |
|---|---|---|
| 「不带锚就拒写」 | 每条结论都指得回痕迹 | **2300 个"我属于第 N 批导入"的合规章**，占全部锚的 63.4% |
| 「去痕迹里搜，看记没记住」 | Theseus 这份是最全的 | **那份对照索引本身被读进过一次会话，在痕迹里留了一份拷贝**——73% 的条目因此"命中" |

**共同点：检验能被「检验本身留下的痕迹」满足。** 一个是盖章满足了格式，一个是问题的副本满足了答案。

**两个都不是恶意，都是自然长出来的。** 这正是麻烦所在——**没有人做错事，检验就这么空掉了。**

**这份规格里所有"抽样核实"性质的断言（U7-4 / U10-4 / U13-3 / U14-3），存在的理由都是这个。**
一个只看形式的检验会说"绿"，而**只有真的顺着回去看一眼，才知道那绿是不是空的**。

### 另一半：会冤枉人的检验，一样坏

**2026-08-10 当天撞见了这个病的反面**，来自实现这一轮的一次自查：

那条"跑完 `/tmp` 残留必须为 0"的检验，写法是**扫一遍 `/tmp`，凡是这个前缀的都不许剩**。
但 `/tmp` 是全机器共用的——**隔壁跑同一份测试时，它会指着别人的目录说我漏了**。实测五次里响一次。

> **一条会冤枉人的检验，用起来和一条不会说"不"的检验一样坏。**
> **它一响，人先怀疑的是检验而不是代码；几次之后就没人当回事了。**

**所以一条检验要同时过两关**：

| | 问题 | 不过关会怎样 |
|---|---|---|
| **它什么时候会说「不」** | 说不出来的，不是检验 | 永远绿着，测不出任何退化 |
| **它会不会冤枉人** | 会，它就会被人学会无视 | 红了也没人看，等于没有 |

**改法是照抄的**：临时目录带上进程号，收尾**只确认这一进程造过的那些**；别人留下的只打印提示，不判。
