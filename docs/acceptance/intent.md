# 意图树：验收规格 U15–U19

> 这份文档回答：**怎么知道 [`docs/requirements/intent.md`](../requirements/intent.md) 里那五条体验真的兑现了。**
>
> 和痕迹那份一样：**还没有代码，验收去塑形。** 所以每条断言都要在**不知道实现长什么样**的前提下说得清。
>
> 断言编号接着 U15–U19 走（`U15-1`、`U15-2`……）。

---

## 五条纪律（沿用 [`trace.md`](./trace.md)）

**一、只从需求推。** 不看设计文档，不看代码。
**二、只走用户看得见的那道门。** 不许摸内部。要是一条断言非摸内部才能验，说明这个体验没被交付到外面。
**三、断言「人的处境」，不是「机制的状态」。**
**四、不是每条都得是代码。** 有些只能扫文档、或者拿真实旧数据量。
**五、不许把实现写进断言。** 反例：「那个节点的父亲字段指向上一条」。正例：**「我问它我在追什么，它给的那句话里每一层都说得出上一层，一直到根」**。

**这一份多一条：**

**六、这一份的红比绿更重要。** 需求 U19 说得很直白：**"免费的信号，现在天天在扔掉"**——一次会话里被纠正三次，三次都被当场吸收了，三次都没留下任何取得出来的东西。**所以凡是断言"某个信号被留下来了"的，绿必须是"我真的把它捞出来看了一眼"，不能是"机制在那儿"。**

## 现在就能跑的四条（不依赖新代码）

有四条断言**只依赖旧系统那棵树，今天就能量**。**先量出现状，再写代码**——不然代码写完了没有对照，说不清是变好了还是本来就那样。

**四条都量完了（2026-08-16）。量的是 `memory/L2_projection/intent_tree/tree.md`（338KB，231 个节点）。**

| | 量什么 | 量出来是多少 |
|---|---|---|
| **U15-6** | 树上的说法和实际发生的事，是不是同一份东西 | **红。231 个节点里只有 173 个（74.9%）指得回一条痕迹**——**四分之一的节点凭空存在** |
| **U16-6** | 那份"防丢视图"到底防没防住 | **红。树里非闭环的 109 条，清单只有 96 行，其中还有 2 条是已闭环的**——**至少 15 条它声称永不丢的节点不在名单上** |
| **U19-8** | 说得出"这是我说的"的节点占多少 | **红。85 个 = 36.8%**（正文带 `[用户原文]"…"` 的）。**三分之二的节点说不出它凭什么是我的意图** |
| **U18-5** | 融合过的两条线，各自的出身还查不查得到 | **今天没有这种记录可查。** 旧树里没有任何一处表示"这两个是一件事"；道路管养 + LLMAD 那次并线在树上完全看不出来 |

### 有一个口径必须写死，不许留解释空间

**U16-6 的"至少 15 条"是按计数算的**，不是按标题对的。

**为什么必须挑明**：拿标题去对两边，对不上的有 46 条和 33 条——因为**那份清单把标题重写成了简称**，同一个意图在两处有两个名字。**按标题算出来的差额是假的（口径把它放大了三倍）。**

所以口径定死：**树里非闭环的条数（109）减去清单里非闭环的行数（96 − 已闭环的 2 = 94），差 15。**

> **这件事本身也是一条发现**：同一个意图在两处有两个名字，**结果是连"对不对得上"都验不了**。新的那棵必须只有一个名字来源。

## U15 · 我随时知道自己在追什么、它从哪来

```
给定   我这一路走了好几跳（停旧系统 → 启停怎么设计 → 人类史上怎么解决 → 换地基 → 写需求 → 沉淀经验 → 痕迹 → 意图树）
当     我在第七跳上问"我在追什么"
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U15-1** | **一句话就说清了** | 答案里既有我此刻在追的这件事，**也有它是从哪个更大的念头分出来的** | "一句话就能说清我在追什么，以及它是从哪个更大的念头分出来的" |
| **U15-2** | **不用我自己想，它摆在那儿** | 新会话一开，我**什么都不问**，这句话已经在我面前 | "这句话不用我自己想，它就摆在那儿" |
| **U15-3** | **走七跳还答得上"当初为什么开始"** | 造一条七层深的路，站在最深那层问。**答案里必须含根那一层**，而且中间六层一层不缺 | "走到第七跳时，'我们当初为什么开始'这句话已经没人答得上来了" |
| **U15-4** | **路只有一条** | 随便挑一个节点问"它从哪来"，**答案唯一**，不出现两条并列的路。**发生过融合之后再问一遍，仍然唯一** | "永远只有一条路——那正是这棵树唯一不可替代的地方" |
| **U15-5** | **树上说的和实际发生的不可能是两回事** | **去改树，改不动**——找不到任何一个"直接编辑树"的地方。能改的只有"发生一件事"，而发生一件事就会留痕 | "这棵树不是另存一份东西，它是从痕迹里看出来的" |
| **U15-6** | **拿旧的那棵量一遍** | 旧树 231 个节点里 **173 个（74.9%）指得回一条痕迹**，**25% 指不回**。新的必须 **100%**——指不回的根本进不来 | 同上 |

> **U15-5 是这条里最硬的一条，也是最容易被做成假绿的一条。**
> "改不动"不是"没提供编辑功能"，是**结构上没有第二份可以改**。
> 验的时候要问自己：**如果我想让树上写的和实际发生的不一致，我会怎么做？说得出做法，这条就是红的。**

## U16 · 我散出去的分支不会丢，想捡的时候捡得回来

```
给定   我开过好几个头，其中一些没走完
当     我哪天想起"当时好像还有个什么"
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U16-1** | **开了头没走完的，列得出来** | 我问"还有什么悬着的"，得到一份名单 | "一个念头开了头没走完，它不会消失" |
| **U16-2** | **每一条都看得到它当时长到哪一步、旁边在聊什么** | 名单上随便挑一条，**它名下发生过的事都在**，不是一句干巴巴的标题 | "包括它当时长到哪一步、旁边在聊什么" |
| **U16-3** | **没有第四种状态** | 随便挑几十条开过头的意图，**每一条都落在三种里**：还悬着 / 我说了不做 / 做完了。**找不到第四种，也没有"悄悄不见了"这种情况** | "它不会消失" |
| **U16-4** | **不催** | 跑上一段时间，**一次催收尾的提示都不许出现**。**需求里明确删掉的那条不许悄悄长回来** | "不需要有人催我收尾。分支本身就有价值，没走完不等于没用" |
| **U16-5** | **收不收，不看时长、深度、数量** | 拿两条各方面都一样、只有"悬了多久"不同的分支进去，**它俩的待遇必须完全一样** | 需求删掉的那条：「"远"本来也没定义清楚（层数深？时间久？还是跟根意图的关系淡了？）」 |
| **U16-6** | **拿旧的那份"防丢视图"量一遍** | 旧的那份**至少漏了 15 条非闭环节点，还混进 2 条已闭环的**（口径见开头）。新的必须 **0 漏、0 混** | "子意图悬空没人收尾，切走的意图回不来" |

> **U16-6 是这份规格里唯一一条"名字本身就是证据"的断言。**
> 那份清单的标题写着"**防丢视图：所有非闭环节点拉平**"。**它自己说了要装下全部，然后漏了 15 条。**
>
> **这跟痕迹那份讲的"检验被形式满足"是同一个病，只是换了个位置**：那边是检验被形式满足，这边是**一个视图被它自己的名字满足了**——名字里有"防丢"，于是没人再去数一遍。

## U17 · 跳走了，我能回来

```
给定   我正在做一件事，临时跳去做别的
当     我回来
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U17-1** | **接着刚才那儿走** | 回来之后我**不用把背景重讲一遍**，也不用重新把自己装回当时的状态 | "回来时接着刚才那儿走，不用重新把自己装回当时的状态" |
| **U17-2** | **我不需要记任何编号** | 我只说"回到刚才那个"，**不给会话编号、不给任何号**，它得找得到 | 现在的办法是"人手写一份交接文件，还得记住一串会话编号" |
| **U17-3** | **不需要谁手写一份交接** | **没有任何人做过"写交接"这个额外动作**，回来仍然接得上 | "一件事需要人手写交接才能接上，说明这个系统没在替你记着" |
| **U17-4** | **拿回来的是当时那一步，不是一份重写的摘要** | 回来看到的东西里，**当时真发生过的事是原样在的**，不是被总结过一遍的版本 | "接着刚才那儿走" |

> **U17-3 和 U12（不需要谁记得去留痕）是同一个要求换了个位置。**
> 那边是"没人记得记一笔，事情仍然在"；这边是"没人记得写交接，我仍然回得来"。
> **两条要是一起红，说明病根是同一个——系统没在替你记着，而是在指望你记着。**

## U18 · 两件事原来是一件，我要能把它们并起来

```
给定   我发现两条线其实在做同一件事
当     我说一句"这俩是一件事"
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U18-1** | **说一句就能并** | 一句话，不用给编号、不用填表 | "我发现两条线其实在做同一件事，说一句就能并" |
| **U18-2** | **两边各自从哪儿来仍然查得到** | 并完之后分别问这两条"你从哪儿来"，**两个答案都还在，而且都是并之前那个** | "并完之后，两边各自从哪儿来仍然查得到——不是把其中一条抹掉" |
| **U18-3** | **并不掉任何一条** | 并完再跑一遍 **U15-4**（路只有一条），必须还是绿的 | 同上 |
| **U18-4** | **复现真事** | 用道路管养的本子 + LLMAD 那份研究：一开始两条独立的线，走到中间发现能并。**并完之后，"为什么这份研究要同时对两个方向负责"这个问题必须答得出来** | "要是并的时候丢掉了'它俩本来是分开的'这个事实，将来就说不清为什么这份研究要同时对两个方向负责" |
| **U18-5** | **今天是空的，得说出来** | 旧树里**没有任何一处表示"这两个是一件事"**——那次真实的并线在树上完全看不出来。**这条不是退化，是从来没有过** | 同上 |

> **U18-2 是这条的全部重量。** "并起来"本身不难——难的是**并完之后不丢东西**。
> 一个把两条线合成一条、抹掉其中一条来头的实现，会让 U18-1 绿、U18-2 红，**而且从外面看起来一切正常**。

## U19 · 它越来越懂我，而且我纠正它不白费

```
给定   它每天都在猜我在追什么（一天几十次），我时不时纠它一下
```

| | 断言 | 怎么验 | 指回需求哪句 |
|---|---|---|---|
| **U19-1** | **它猜的那部分，我一眼看得见** | 它讲"你在追什么"的时候，**哪几句是它猜的、哪几句是我认过的，我不用琢磨就分得开** | "它每次把'我在追什么'讲出来，我一眼看得见——所以它讲错了我才会开口" |
| **U19-2** | **一句话就能纠** | 我说"不是这个意思，是 X"就完事，**不给编号、不进任何菜单** | "我一句话就能纠" |
| **U19-3** | **纠过的取得出来，而且是成对的** | 过一段时间去捞"它猜错了什么、我改成了什么"，**捞出来必须成对**——只有猜没有纠，或者只有纠不知道纠的是什么，都算红 | "它猜错了什么、我改成了什么，都留得下来，将来取得出来" |
| **U19-4** | **我不吭声也被记下来** | agent 提了、我没答。**这件事本身查得出来**（谁提的、提了什么、什么时候） | "我不吭声，也是信号……这类信号比出言修正更多、更便宜，而且现在一条都没被捡" |
| **U19-5** | **但它不算树上的洞** | 上面那条没答的**不出现在"我在追什么"里**，也不出现在"还有什么悬着的"名单里 | "agent 问了、我没答，那不是树上的洞。它是关于 agent 的信号" |
| **U19-6** | **没有我的一句话，长不出节点** | 让一个 agent 直接去认一个意图（不经过我说话）——**树上不许多出这个节点** | "agent 提的东西不自动成为节点——只有我接了它，它才是" |
| **U19-7** | **记号和颜色分开验** | 把交互记录**当纯文本处理**（去掉一切颜色和显示效果），**"它猜的"和"我纠的"仍然捞得出来** | "颜色是给眼睛的……某种固定的记号是给机器的——留在记录里、将来从一堆对话里能捞出来的，是记号不是颜色" |
| **U19-8** | **拿旧的那棵量一遍** | 旧树 231 个节点里只有 **85 个（36.8%）** 说得出"这是我说的"。新的必须 **100%**——说不出的根本进不来 | 同上 |
| **U19-9** | **复现那三次被扔掉的纠正** | 需求里点名的三次：`supervisor` 这个名字不合规矩、"事件表"该叫痕迹、"不保留第二个知识库"说的是 PKM 不是别的。**三次都当场吸收了，三次都没留下任何取得出来的东西。** 走一遍同样的三次，**三次都必须捞得回来** | "三次都被当场吸收了，三次都没留下任何取得出来的东西——它们只活在这段对话里，而这段对话已经被压缩过一次" |

> **U19-7 是这五条里最容易做成假绿的一条。**
> 一个只做了颜色的实现，在人眼前看着完全正确——**而它对将来一点用都没有**，因为颜色不进文本，捞不出来。
> **验法必须是"把颜色全部去掉之后还剩什么"**，不能是"看起来分得清"。

> **U19-4 和 U19-5 是一对，缺一条另一条就变味。**
> 只有 U19-4：没答的东西被留下来了，但要是它同时挂在树上，就成了需求明确否掉的那个"洞"。
> 只有 U19-5：它不在树上，但也没被留下来——**那就是今天的状况，一条都没被捡。**

> **U19-9 是整份规格里唯一一条直接复现真实损失的。**
> 它验的不是机制，是结果：**同样的三次纠正走一遍，捞得回来吗。**
> 这条是纪律六的具体形态——**绿必须是"我真的捞出来看了一眼"。**

## 为什么这里没有「agent 提了多少条、我接了多少条」这种指标

需求 U19 ④ 说得清楚：我不吭声是信号，**三种可能——上下文没给够、没讲清楚、这事本来不重要——三种都指向 agent 该改哪里。**

**但"该改哪里"是三选一，不是一个比率。** 一个"接受率 37%"的数字，三种情况混在一起，**指不出任何一个该改的地方**。

**所以这一轮只验"信号留下来了、捞得出来"（U19-4 / U19-5 / U19-7），不验"信号被用来改进了什么"。**

**这不是含糊过去，是把它明确留到下一轮**：需求里已经写了这棵树是"将来那个用户模型的原料"，**而原料能不能用，要等真的有人去用它的时候才验得了。现在造一个指标，是在验一个还不存在的消费者。**

---

## 一条要防的病：这份规格自己会被"机制在那儿"满足

痕迹那份规格总结过一个病：**检验能被"检验本身留下的痕迹"满足**（2300 个合规章满足了"不带锚就拒写"；一份索引被读进对话，于是 73% 的条目"命中"）。

**这份规格有它自己的变种，而且更隐蔽：**

| 断言 | 本来要保证什么 | 可能被什么满足 |
|---|---|---|
| **U19-3**（纠过的取得出来） | 我纠的东西将来用得上 | **一个"纠正记录"表存在，但从没人打开过。** 表在那儿，条数在涨，没有一条被捞出来看过 |
| **U19-1**（猜的看得见） | 它讲错了我才会开口 | **颜色对了，但记号没进文本。** 人眼前完全正确，将来一条都捞不出来 |
| **U16-1**（悬着的列得出来） | 分支不丢 | **名单存在，但它自己漏了几条。** 旧系统就是这么失败的，而且名字里还写着"防丢" |

**共同点：机制在那儿，但没人验过它的输出。**

**所以这份规格里凡是带"取得出来 / 捞得出来 / 列得出来"的断言（U16-1 / U16-6 / U19-3 / U19-7 / U19-9），验的方式只有一种：真的取一次，看一眼取到的是什么。**

**判一条检验合不合格的标准只有一个：它什么时候会说「不」。说不出来的，就不是检验。**

## 这份规格自己的验收

跑完要能回答一句话：**"U15 到 U19，哪几条绿了。"**

**今天已经有四条红，而且是量出来的**（U15-6 / U16-6 / U18-5 / U19-8）。它们是对照，不是失败——**先量出现状，代码才有个照着长的东西。**

**代码写完的那一刻，这里不该有红的。有红，说明代码没照着规格长。**
