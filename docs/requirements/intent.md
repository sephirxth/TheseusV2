# 意图树：用例与体验

> 这份文档只写**一个人要干什么、他应该体验到什么**。一个技术名词都不出现。
>
> 具体用什么手段做到，见 `docs/design/intent.md`（**还没写**）。
>
> 一条规矩：**每个用例都得说得出"为什么这条重要"，而且理由必须是真发生过的事。** 说不出来的是想象出来的需求，删掉。
>
> 编号接着 [`trace.md`](./trace.md) 的 U7–U14 往下排。
>
> **这棵树不是另存一份东西，它是从痕迹里看出来的。**（2026-08-08 游渊定）意图是因，发生的事是果；因果本来就在痕迹里，这棵树只是把"因"那一侧显出来。**所以不会出现"树上写的"和"实际发生的"是两回事。**
>
> **树上的节点是"我"的意图**（2026-08-08 游渊定）。agent 提的东西**不自动成为节点——只有我接了它，它才是**。
>
> 由此推出一条：**agent 问了、我没答，那不是树上的洞。** 它是关于 agent 的信号，三种可能——上下文没给够、没讲清楚、或者这事本来就不重要。**三种都是 agent 该改的地方，不是我该补的作业。**

## 为什么是树

游渊的原话：「每件事确实后面有一个**起始动机**，有发展，也可能会和别的想法**融合**。」

这句话里有两件都为真、但互相打架的事：**起始动机唯一**（是树），**融合**（把树破了——一个东西有了两个来头）。

**解法：树说的是出身，不是现在的关系。**

- **出生**：每个意图有且只有一个"它是从哪儿分出来的"。这些关系构成一棵真正的树。
- **融合**：后来才发生的另一种关系，**不改出生地**。

这样两边都保住了：融合能如实记下来，而"我现在在追什么、它从哪来"**永远只有一条路**——那正是这棵树唯一不可替代的地方。列表说不出"从哪来"；网说得出，但说不出**唯一的**一条，于是看不出"我在哪"。

> **一条删掉的需求**：VISION 里那句「分叉走远时主动提醒回归」——**2026-08-08 游渊定：不要。** 而且"远"本来也没定义清楚（层数深？时间久？还是跟根意图的关系淡了？）。

## U15 · 我随时知道自己在追什么、它从哪来

**我应该体验到**：任何时刻，**一句话就能说清我在追什么，以及它是从哪个更大的念头分出来的**。这句话不用我自己想，它就摆在那儿。

**为什么这条重要**：光这一次会话就走过——停旧系统 → 启停该怎么设计 → 人类史上怎么解决 → 换地基 → 写需求 → 沉淀经验 → 痕迹 → 意图树。**七跳。** 中间没有任何一跳是错的，但走到第七跳时，**"我们当初为什么开始"这句话已经没人答得上来了**，除非往回翻。

这也是项目规矩里为什么要求每次回复开头写出这条路径——**那条规矩就是这个需求的手工版**。

## U16 · 我散出去的分支不会丢，想捡的时候捡得回来

**我应该体验到**：一个念头开了头没走完，**它不会消失**。我哪天想起"当时好像还有个什么"，就该找得到——**包括它当时长到哪一步、旁边在聊什么。**

**不需要有人催我收尾。** 分支本身就有价值，**没走完不等于没用**（2026-08-08 游渊：「总有些树的节点被漏掉，但是我觉得这些分支也有价值」）。

**为什么这条重要**：VISION 里写着「子意图悬空没人收尾，切走的意图回不来」，并且注明这个需求**「在多次真实交互中独立、反复涌现」**——反复自发涌现本身就是最强的信号。

**一个诚实的观察**：我去翻眼下能找得到的悬着的东西，找到的**全是已经被写下来的那些**——AGV 消失的 bug 暂搁、Bevy demo 黑屏待解、判例账缺一种事件待补、闲置索引膨胀待定规矩。**看不见的那些我找不到，正因为它们看不见。**

这恰好说明这条要的是什么：**不是催，是让分支留下形状。** 写下来的那几件之所以还在，靠的不是谁记性好，是它们**留下了形状**。

## U17 · 跳走了，我能回来

**我应该体验到**：临时跳去别的事，回来时**接着刚才那儿走**，不用重新把自己装回当时的状态。

**为什么这条重要**：现在的办法是**人手写一份交接文件，还得记住一串会话编号**（`handoff-20260611-session-3cc78184`）。**一件事需要人手写交接才能接上，说明这个系统没在替你记着。**

---

## U18 · 两件事原来是一件，我要能把它们并起来

**我应该体验到**：我发现两条线其实在做同一件事，**说一句就能并**。并完之后，**两边各自从哪儿来仍然查得到**——不是把其中一条抹掉。

**为什么这条重要**：真发生过。道路管养的本子和 LLMAD 那份研究，最后是**一份研究出两个本子**、共用同一个内核。它们一开始是两个独立的念头，是走到中间才发现能并。

**要是并的时候丢掉了"它俩本来是分开的"这个事实，将来就说不清为什么这份研究要同时对两个方向负责。**

## U19 · 它越来越懂我，而且我纠正它不白费

**我应该体验到**：

- 它每次把"我在追什么"讲出来，我**一眼看得见**——所以它讲错了我才会开口
- 我一句话就能纠
- **纠过的不白纠**：它猜错了什么、我改成了什么，**都留得下来，将来取得出来**

**为什么这条重要**：

① **这是"越来越懂我"眼下唯一的落地物。** 不是说以后也不造一个正经的"用户模型"，是**暂缓**——**现在造不出终极形态，得靠迭代长出来**（2026-08-08 游渊定）。所以这棵树同时是两样东西：**今天那个模型的可见形态**，以及**将来那个模型的原料**。看不见的理解没法纠，纠不了就不会变准，不变准就长不出下一版。

② **免费的信号，现在天天在扔掉。** 光这一次会话，我就被纠正了至少三次：`supervisor` 这个名字不合规矩、"事件表"该叫痕迹、"不保留第二个知识库"说的是 PKM 不是别的。**三次都被当场吸收了，三次都没留下任何取得出来的东西**——它们只活在这段对话里，而这段对话**已经被压缩过一次**。

③ **猜测本来就在发生**，一天几十次（项目规矩要求每轮回复开头写出那条路径）。**猜在发生，纠也在发生，只是没人把这对东西捡起来。**

④ **我不吭声，也是信号。** agent 问了我没答，说明三件之一：上下文没给够、没讲清楚、这事本来不重要——**三种都指向 agent 该改哪里**。这类信号比"出言修正"更多、更便宜，**而且现在一条都没被捡。**

**这条对"看得见"和"取得出来"的要求不是一回事，得分开满足**：颜色是给眼睛的——看不见我就不会纠；某种固定的记号是给机器的——**留在记录里、将来从一堆对话里能捞出来的，是记号不是颜色。**
