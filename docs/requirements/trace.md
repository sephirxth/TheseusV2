# 痕迹：用例与体验

> 这份文档只写**一个人要干什么、他应该体验到什么**。一个技术名词都不出现。
>
> 具体用什么手段做到，见 `docs/design/trace.md`（**还没写**）。
>
> 一条规矩：**每个用例都得说得出"为什么这条重要"，而且理由必须是真发生过的事。** 说不出来的是想象出来的需求，删掉。
>
> 编号接着 [`lifecycle.md`](./lifecycle.md) 的 U1–U6 往下排，不重新数——这样一个编号在整个系统里唯一。
>
> **"痕迹"这个词来自 VISION**（"必须要以某种可被语言和视觉观测的形式留下痕迹"）。不叫账本、不叫事件表、不叫日志。
>
> **这个模块其实是两个动作、一份东西**（2026-08-08 游渊点破后厘清）：
> **痕迹** = 留下的那份东西 · **留痕** = 写它（只有 U12）· **回忆** = 读它（其余七条全是）。
> 之前"八条里只有一条是写的"这个比例读着别扭，原因就在这儿——**不是比例失衡，是两件不同的事被塞进了一个词里。**
>
> **用例里不写命令**（2026-08-08 游渊定）。命令行是**一种**实现——人可能在终端敲、可能在面板上点，**也可能就是跟 agent 说一句话**；最后这条对 Theseus 尤其真，而写死命令等于把它挡在门外。用例只写"我要做的事"，怎么做归 [`docs/design/trace.md`](../design/trace.md)。
>
> **这条是事后补的，而且有代价证据**：为了一个命令名来回三轮（`why` → `trace` → `recall`）——**那场争论本身就是症状，它根本不该发生在需求文档里。** 那三轮的分析没扔，挪进设计文档了。

## U7 · 我要能查"刚才那件事**为什么**发生"

**我要做的**：问「这件事为什么会发生」。

**我应该体验到**：顺着往回一路查，**每一步都指得出它的上一步**，一直查到一个我认得的起点——我说的一句话、一个到点的时刻、一条从外面进来的消息。**中途不许断。**

也不需要我猜。不会出现"这儿应该是那个东西触发的吧"这种句子。

**不这么做会怎样**：

> 我问「昨天半夜那份东西是怎么发出去的」。它给我一条链子，**一步不缺**，我一路跟到底。
>
> 最后一步写着：**因为两分钟到了。**
>
> 我再往上问一句，它说没有上一步了，这就是起点。**它没答错，它答完了。** 屏幕上摆着一次干干净净的追查，看起来和一次成功的追查一模一样——**只有我知道我什么也没问出来。**
>
> **另一头是"修过头"**：要是我嫌这种答案没用，改成"每条链子都必须查到一句人说的话"，那些本来就该由时钟起头的事会被一律判成断掉。**这个错真犯过**——这条用例最早写的理由是"一半是断头路"，就是这么算出来的，后来发现根本不成立。**一个把好的判成坏的检验，会让我从此不信这个检验。**

**为什么这条重要**：

> ⚠ **这条的理由我一开始写错了。** 原来写的是"只有 46.6% 说得出因为什么，剩下一半是断头路"。
> 2026-08-09 用真实账本重算，那个说法不成立——**它把"本来就该没有上一步的起点"当成了"断掉的链子"。**

真实情况是**链子基本是连的**：排掉心跳和定期扫描后剩 26741 条真事件，**97% 以上都能一路查到一个合法的起点**，真正指向"一条不存在的事件"的只有 **0.2%**。

**问题不在断，在于查到底之后落在哪儿。**

| 查到底落在 | 占比 |
|---|---|
| **时钟到点** | **78.8%** |
| **你说的一句话** | **17.4%** |

你问"这事为什么发生"，答案是"因为两分钟到了"——**技术上没断，实际上等于没答。**

**一条完整但无意义的链子，和一条断了的链子，用起来是一样的。**

另有 **0.9%** 是真断的，而且**断的位置特别扎眼**——几乎全集中在"系统观察自己"这一类：记下"我被意外了"却没记被什么意外（431 条）、意图树更新了没记为什么（177 条）、发现自己漂移了没记怎么发现的（82 条）、记下一次纠正却没记纠的是什么（6 条）。

**系统干活的痕迹是连的，系统认识自己的痕迹是断的。** 而后者正是 U10 和 U19 要靠的那部分。

## U8 · 我要能查"这件事**为什么没**发生"

**我要做的**：问「这件事为什么**没**发生」。

**我应该体验到**：**没做的事，和做了的事一样留痕。**

系统决定不做、决定推迟、把两件事当成一件、把一个请求丢掉——**这些决定本身要留下来，还要留下它当时凭什么这么定。**

**不这么做会怎样**：

> 我先说「装 numpy 2.1.0」，过一会儿又说「装 2.2.0」。回来一句「好了」。
>
> 装上的只有一个。系统觉得这两句话像得够多，当成了同一件事，**把后一句直接扔了——扔的时候一声没吭。**
>
> 我不放心，回头把那两天的记录从头翻到尾，找有没有哪一行写着"合并""重复""丢掉"这类字眼：**一行都没有。** 记录通篇是绿的——请求收到了、活干完了、没有报错、没有警告。**那件没发生的事，在记录里也没发生。**
>
> 同一个毛病还吞过别的：**两笔转账，500 元和 800 元，只走了一笔。** 我要是不去对账，这件事永远不会有人提。
>
> 而它最后是怎么露出来的——**有人去读了那段代码**，看见了那句"够像就算一件事"。**一个非得读代码才能发现的毛病，等于根本没留痕。**

**为什么这条重要**：旧系统里有一处判断，两个请求文字够像就当成同一个，后来那个静默消失。实测被吞掉的：numpy 2.1.0 和 2.2.0（像 95.5%）、PR #412 和 #418（94.1%）、周报 08-04 和 08-05（94.1%）、转账 500 元和 800 元（90.9%）——**一声不吭。**

它最后是被人去读代码读出来的，不是被查出来的。**一件事没发生，本来就是最难查的一种事；而它恰好最不留痕。**

## U9 · 我要一眼看见有意义的事，不被心跳淹掉

**我要做的**：看看最近都发生了什么。（也要能要求"把心跳也给我看"，但那不该是默认。）

**我应该体验到**：翻开就是"发生了什么"，不是一屏又一屏每两分钟一条的自动心跳。

**不这么做会怎样**：

> 我想知道这两天都发生了什么。翻开——心跳、心跳、心跳。我往下滚了三十屏，**还是每两分钟一条的心跳**。滚到第五屏我其实已经不在看了，只是在滚。
>
> 那个月真正值得看的一共 194 条。**它们就在这一万两千条中间，我一条也没碰上。**
>
> 而这份记录**没有坏**：一条不缺，每一条都对，看上去比什么时候都完整。**恰恰是"它很完整"这件事，让我一直相信"想查的时候查得到"。**
>
> **另一头是"那就把心跳藏干净"**：藏干净之后，"心跳停了"这件事也跟着看不见了——**而心跳停了，正是唯一能告诉我"它死了"的东西。** 从此安静有两种意思，我分不出是哪一种。

**为什么这条重要**：旧系统 8 月记了 **12862** 条，其中 **98.5% 是自动产生的**——触发器自己记账 5450、时钟到点 5357、定期搬运 1504、主动思考的两类记账 357。

**值得一看的，一整个月只有 194 条。**

这 194 条里，**"你说了一句话"占 5 条**。**同一个月，它给时钟记了 5357 笔。**

**一份 98.5% 是噪音的记录，和没有记录差不多——区别只在于它还占着 89MB。**

> ⚠ 这个数改过两次，把过程留下：先写 12794 / 95.8%（粗算），再改成 12828 / 96.8%（一次基线测量，**分项与小计相加对不上，虚高了约 220 条**），2026-08-10 第三次实测得到现在这组。**分项摆在眼前却没相加核一遍，是这次的教训。**

## U10 · 系统自己也读这份痕迹

**我应该体验到**：**我对它的了解，和它对自己的了解，来自同一份东西。**

不会出现"文档里写它这么干"和"它实际那么干"是两回事。它反思自己、总结自己、改自己，凭的是这份痕迹，不是凭一份人手写的自我介绍。

**不这么做会怎样**：

> 我问它「你是怎么决定哪些事要先问我一声的」。它讲得很清楚，条理分明，我听完就放心了。
>
> 它讲的是**一份写在文档里的自我介绍**。那份介绍半年前是对的；实际的做法三个月前改过一次，改的人没回来改这份介绍。
>
> **它不是在骗我，它真的这么以为。** 我也没法从哪儿看出异样——**它答得越顺，我越信。**
>
> 这两件事分家的那一天，**什么动静都没有**。我最后是这么发现的：某天它做了一件按它自己讲的那套明明不该做的事，**而我的第一反应是怀疑我自己记错了。**

**为什么这条重要**：这是 VISION 里写死的一条——"这种日志是给系统自己看的，所以格式上要对系统友好"。而旧系统的自我认知是手写在文档里的：**一份手写的自我认知，和实际行为之间没有任何东西保证它俩一致；不一致的时候，也没有任何东西会喊一声。**

## U11 · 我要它一年后还能用

**我应该体验到**：痕迹会一直长，这没办法。但**翻它的代价不能跟着一直涨。**

**不这么做会怎样**：

> 我想问一件很小的事：这四个词在我的记忆里出现过没有。我拿这四个词挨个去搜整份记忆，然后等。**两分钟过去，什么都没回来，我自己把它掐了。** 换一个小得多的范围重问一遍，才拿到答案。
>
> 这件事今天真发生了，而且发生了两回，就在写这份文档的时候——第二回是想数一数这份记录一共有多少字，**同样两分钟没回来，同样只能作罢。**
>
> **没有任何东西坏了**：记录全在，问法也对，它只是慢到我不会再问第二遍。于是我的习惯变了——以后想查什么，我先在心里估一下值不值得等，**大部分时候答案是不值得**。一份没人愿意翻的记录，和没有记录差不多。
>
> 而它一天也没停过：写下"105 天 89 MB"到今天，**我重新量了一遍，115 天、93 MB**（量的是文本本身，不是它占了多少盘——这个坑 U14 底下踩过一次）。
>
> **另一头是"那就定期把旧的删掉"**：删完之后我问一件去年的事，它答"没有记录"。**这句话和"这件事根本没发生过"长得一模一样**——我分不出是本来就没有，还是被我自己清掉了。

**为什么这条重要**：三处同一个病。① 旧账本 105 天 89MB，还在长；② 另一份只补记、从不删的文件涨到 589KB，"只留最近几条"的规矩至今没定；③ **启停模块自己也留着这个缺口**（★3：输出文件只追加、不轮转）。

**三个地方各自独立地得了同一个病，说明这不是疏忽，是默认结局。**

## U12 · 我不需要谁「记得」去留痕

**我应该体验到**：事情发生了，痕迹就在。**不靠哪个人、哪个 agent 记得多敲一条命令。**

**不这么做会怎样**：

> 昨天我跟它聊了一整轮，问题问了，答复也拿到了，很顺。今天我接着往下说：「按昨天讲的那个办法办。」
>
> 它问我：**「哪个办法？」**
>
> 在它那边，昨天那一轮**从来没有发生过**。回复的那一半做了，记账的那一半忘了。而昨天当时我一点异样都感觉不到——**回复是好的，对话是顺的，没有任何一处报错。**
>
> **后来打的补丁更值得看**：办法是在叮嘱里加一句"记得要记"。管用了一阵子，**然后某一次又忘了。** 我说不出是哪一次——**忘掉的那一次，恰好就是没留下痕迹的那一次。** 这种漏只能等下回撞上才知道，撞不上就一直不知道。

**为什么这条重要**：旧系统里，"回复用户"和"把这件事记下来"是两个动作。负责回复的那个副本经常做完前一个、忘了后一个。结果是——**对用户来说这轮交互发生了，对系统来说它从没发生过。**

后来的办法是在提示词里硬写"必须记得"。**用一句叮嘱去堵一个结构问题，是在赌运气，而且每一次都要重赌一遍。**

> 这八条里，**U12 是唯一一条「写」的，其余七条全是「读」**。这个比例不是巧合：读的需求容易想到，写的需求要等它漏了才被发现。

## U13 · 旧的记忆整个接进来，不留在墙那边

**我要做的**：问一件很早以前发生的事——**用问今天那件事完全一样的方式。**

**我应该体验到**：我问一件事，**不用先想它发生在新旧分界线的哪一边**。同一个问法，同一份痕迹。

旧 memory 不是"归档"、不是"参考资料"。**它就是这个系统记忆的一部分**，搬完之后仍然是活的。

**不这么做会怎样**：

> 我想起一件三月定下来的规矩，想问一句。**话到嘴边我先卡了一下：三月那会儿还是旧的那套。**
>
> 于是我做的第一件事不是问，是先判断这事该去哪边问。判断错了，再问一遍。
>
> **麻烦的是问错了我也不会知道**：我问新的这边，它说"没查到"。这句话在"确实没这回事"和"这条在墙那边"两种情况下**是同一句话**。我拿到一个否定的答复，而它可能只是我问错了地方。
>
> **另一头是"搬进来了就当它一样好用"**：我照查今天那件事的法子，往回查一件三月的事。链子确实一步不缺，一路通到底——**落在"因为两分钟到了"。** 搬得进来的是记录和链子，**搬不进来的是"这条链子有意义"**。要是不把这句话明写出来，我会以为分界线两边一样查得动，**然后拿一个什么也没查出来的答案当结论用。**

**为什么这条重要**：到今天为止已经攒了 105 天、139586 条事件、15G 对话。**要是 V2 只从今天开始，那我未来一年里每一个"为什么"都可能撞墙**——而且撞上的时候，我还得自己判断"这事该去哪边查"。**这正是 U2 里那条病：顺序只存在于我脑子里。**

**诚实的限制（必须写在这儿，不许含糊）**：接进来的这批，链子大体是连的（真断的只有 0.2%），**但 78.8% 的链子查到底落在"时钟到点"**——那是个合法起点，可它答不了"为什么"。

所以 U7 那句"一直查到一个我认得的起点"，**在分界线之前只有 17.4% 能真正做到**。能给的是"记录在这儿、链子也在"，给不了"这条链子有意义"。**不能让它看起来像做到了。**

## U14 · 换个 agent、换个会话，它还记得我们聊过什么

**我应该体验到**：我在这台机器上跟**任何一个** agent 说过的话，都进同一份痕迹。

换 agent、开新会话、上下文用光了重开——**新的那个接得上，我不用重讲一遍**。我也不需要记得"上次是跟谁说的"，我只说"我上次讲过的那个事"，它就该找得到。

**不这么做会怎样**：

> **第一种**：上下文用光了，我开一个新会话。新的那个一上来干干净净——**干净得像我从来没跟它说过话。** 我说"接着昨天那个做"，它问"昨天哪个"。这台机器上收着的那一大堆对话就在原地躺着，**对刚开的这个来说等于不存在。**
>
> **第二种更难看出来**：我从另一份索引里挑了四个词，挨个到 Theseus 自己那份记忆里去问。头两个问得出来，我心里一松——**这份记忆是全的。** 后两个，`firecrawl` 和 `chubbyskills`，**一个字也问不出来。**
>
> 而这四条在那份索引里是并排放着的，**长得一模一样，没有任何东西标出后两条是缺的**。我要是只碰巧问了头两个，我会带着"它全都记得"这个结论走开，**而且从此不再核。**
>
> **这不是"记忆是空的"那种坏，是"记忆只有一半"。** 空的我一眼就不会信；一半准的，我会信，然后在某个我没法预料的地方被它坑一次——**到那时我的第一反应还是"我自己记错了"。**

**为什么这条重要**：

① **记录其实已经在收了**——本机 15G 对话，claude / codex / deepseek / hermes 四家都在收。**但收着不等于记得**：新会话一开，那 15G 对它等于不存在。

② 每个 agent 又各自造了一份自己的记忆——Claude Code 在 `~/.claude/projects/<项目>/memory/` 下就有一份。

**并存本身不是问题**（2026-08-08 游渊定：这些删不掉，允许长期共存；"本地不保留第二个持久知识库"那条说的是 PKM，不是它们）。**问题是 Theseus 这份必须是最全的那一份**——而现在没有任何东西保证它是，也没有任何东西会在它变得不全时喊一声。

**这不是担心，是已经发生了**：从 Claude 那份索引里随手挑四条，去 Theseus 自己的记忆里找——`taildrop`、`cloudzy` 找得到，**`firecrawl`、`chubbyskills` 一处都没有。**

> 顺带暴露了另一件事：这个核查只查得动小的那部分（**纯文本 5.87 MB**）；大的那部分有 17G，**扫不动，只能作罢**。"想查一遍要多久"本身就是 U11 说的那个病。
>
> ⚠ **这个数原来写的是 28M，错了，2026-08-16 改正。** 28M 是 `du` 报的**磁盘块占用**——那底下 2514 个小文件，块对齐把真实的 5.87 MB 撑到了 28 MB（连非文本一起算也只有 19.51 MB）。**量的是"这堆东西占了多少盘"，报的是"文本有多少字"，偏了 4.8 倍。** 错的一方是我。留着，因为它是同一类毛病里最干净的一个例子：**别量装东西的容器。**

③ 那份自己造的索引里，眼下还写着"⚠️路径存疑""下次要用时先重新定位"——**一份需要人提醒"这条可能不准"的记忆，本身就说明它不可靠。**

**这条比 U7 难，难在一个地方**：U7 是**我主动去查**，U14 是**我没问，它就该已经知道**。后者意味着必须有东西替我判断"什么算相关"。这是这八条里唯一真的需要"找相关内容"的地方。

## 一件我没写成用例的事

**"痕迹不能丢、不能重"** —— 我想写，但按开头那条规矩，我说不出它在这个项目里真出过什么事，所以不给它用例的位置。

而且它本来也不是"一个人要干的事"。它是上面**八条全部**能不能成立的**前提**：痕迹一旦丢了或重了，U7 到 U14 会**同时悄悄变成错的，而表面上一切正常**。

**"坏了还长得像好的"是这套系统迄今最贵的失败方式**——2026-08-05 我宣布旧系统已停，用的证据是"记录不再增长"；那条证据在"真停了"和"我看的窗口太短"两种情况下都成立，而当时是后者，之后又写进去 269 条。

所以这件事归到技术实现那边当硬约束，不占用例的位置。
