## 0. 一句话

**意图树不是一张新表，是痕迹表上的一次折叠。**

- 只有"我认了"的那几条痕迹长成节点；
- 一个节点的父亲，**就是它出生那一刻我正在追的那条**；
- 融合、修正、放弃，都是后来追加的痕迹，**一条也不改历史**。

这句话是需求文档开头那两条前提的直接后果，不是新主张：

| 需求里的前提 | 落到设计上是什么 |
|---|---|
| "这棵树不是另存一份东西，它是从痕迹里看出来的" | **树没有自己的存储**。它是一个折叠函数的输出，输入只有 `trace` 那张表 |
| "树上的节点是'我'的意图；agent 提的东西不自动成为节点——只有我接了它，它才是" | **哪条痕迹能长成节点，是一次查询，不是一个字段**。见第二节 |

| **指得回一条痕迹的节点** | **173 个 = 74.9%**（正文里带 `[[L1_ledger/…]]` 锚的） |
| **"防丢视图"漏了多少** | 树里非闭环的有 **109** 条，那份自称"所有非闭环节点拉平"的清单只有 **96** 行，**其中还有 2 条是已闭环的**——**至少 15 条非闭环节点不在这份"防丢"清单上** |

# 一、树怎么从痕迹里长出来

## 1.1 七种痕迹，只有一种长节点

| 痕迹类型 | 谁写得出 | 折叠时做什么 |
|---|---|---|
| `intent.proposed` | **agent 随便写** | **什么都不做。不长节点。** 这是"我猜你想要 X" |
| `intent.adopted` | 要过第二节的判据 | **长一个节点**，父亲 = 出生那一刻的当前，当前移到新节点 |
| `intent.resumed` | 同上 | 当前移到一个已有节点 |
| `intent.corrected` | 同上 | 换掉某个节点的**现在的说法**（旧说法留在原处，一个字不动） |
| `intent.dropped` | 同上 | 标成"我不做了"；被指的要是一条提议，就是"这条我不要" |
| `intent.done` | 同上 | 标成"做完了" |
| `intent.merged` | 同上 | 在两个节点之间加一条**非出生边**（第五节） |

**一条规则管住全部**：**除了 `intent.proposed`，其余每一种都要过同一道判据。** 不列例外表——例外表是将来漏洞的所在地。

**提议不进折叠。** 这不是遗漏，是需求前提二的直接后果：树上只有我认的。提议留在痕迹里，用另一种方式被捡（第三节）。

## 1.2 折叠函数长什么样

折叠的状态只有两样：**当前是哪个节点**，以及**每个节点的现在的样子**。

```
状态 = { 当前: 节点号 | 无,
         节点: { 节点号 → { 说法, 父亲, 状态(悬着/做完了/不做了), 并过的那些 } } }
```

一个 switch，六个分支，每个分支改一处状态。**十几行。**

**这是照 DeepSeek Harness 的做法。** 他们的 `applyGoalProjection`（`packages/goal/goal/src/index.ts:96–113`，连签名带大括号 18 行）就是这个形状：一个事件进来，认识就折，不认识就原样返回。**复杂的是判据，不是代码。** 判据在门上（第二节），不在折叠里；折叠只认已经进来的痕迹，因为**进不来的写不出来**。

> 这条"判据在门上、不在读的时候猜"，也是 [`trace.md`](./trace.md) 自己的教训——U10-4 就是从"事后抽样"改成"写时当场拒"的。同一个道理第二次用。

## 1.3 节点没有自己的号

**一个节点就是那条 `intent.adopted` 痕迹本身**，用它的痕迹号。

**为什么**：少一套号就少一处会对不上的地方。而且旧文档里那些 `[[L1_ledger/events/YYYY-MM-DD#evt-…]]` 锚**天然就指得中节点**——[`trace.md`](./trace.md) 第七节为了保住 699 个锚而决定不换旧号，这里白捡了同一份好处。

**谁的做法**：git 的 commit——一个 commit 没有另一套编号，它就是那个对象。

## 1.4 出生边：默认取"当时的当前"，不给显式的父亲字段

**父亲不写在痕迹里，是折叠时算出来的**：折叠按时间顺序走，走到一条 `intent.adopted` 时，它的父亲就是此刻的当前。

**为什么不给一个"父亲"字段**：给了，就有了两个说法——字段里写的，和实际发生的。**而需求第一条前提说的就是"不会出现树上写的和实际发生的是两回事"。** 一个可以被填错的字段，是这句承诺唯一可能破的地方。

**备选方案，以及为什么放弃**（照 DSH 的 Agent Note 规矩：记下考虑过又放弃的路）：

**带一个 `父亲=<节点号>` 的字段。** 好处是能直接挂到一个老节点上，不必先"回去"。放弃的理由有两条：一是上面说的两个说法；二是**它想解决的问题已经有答案了**——要挂到老节点上，先 `intent.resumed` 回到那儿，下一条 `adopted` 自然就挂在那儿。而"回去"这个动作本身正是 U17 要留痕的东西。**一个字段被删掉，同时一条需求被满足，这是划算的那种删。**

## 1.5 一次只有一个"当前"

**当前是我的，不是某个会话的。** 我一次只在追一件事，切走是一个动作，会留痕——**这正是 U17 能成立的原因：回来不靠谁记得，靠那条切换痕迹。**

**那多个 agent 同时在干活怎么办？** 它们不各自持有一个"当前"：

> **每个会话开场时被系上一个节点**——它被派出来那一刻的当前。此后这个会话的路径就固定了。我的当前继续动，不影响已经系好的会话。

所以项目规矩里那条"回复开头写出意图树路径"，写的就是**这个会话被系在哪儿**，而不是"此刻我在追什么"。两者以前是混着的，现在分开了。

**谁的做法**：DSH 的目标是**每个会话一个当前值**（`ctx.goals.get(agent)`，按会话取）。我们把范围从会话挪到人，因为需求要的是"我在追什么"，不是"这个会话在追什么"。**范围变了，形状照搬。**

★1：**"一次只有一个当前"够不够用，没实测。** 人同时推两件事的时候会怎样，得跑起来才知道。

# 二、"是不是我的意图"——一次查询，不是一个字段

**这一节是整份设计里最要紧的一节。** 需求前提二（树上只有我认的）和 U19（纠正不白费）全压在它上面。

## 2.1 先看别人怎么做的：DeepSeek Harness 的 `direct-human`

读的是 `packages/goal/tool-goal/src/authority.ts`（源码在 `/home/youyuan/Theseus/refs/deepseek-harness`）。

**它的形状是这样的**：

| | 他们怎么做 | 在哪 |
|---|---|---|
| 目标操作只认两种身份 | `{ kind: 'direct-human' }` 或 `{ kind: 'goal-round', goal }` | `authority.ts:20-22` |
| **"是人"是一次对事件流的查询** | 顶层 agent 的**当前这一轮**里，存在一条消息且它的来源标记是"人" | `authority.ts:70-74` |
| **没有任何地方可以把它设成真** | 整个文件里没有 setter、没有字段、没有标志位 | 全文 |
| 创建目标、改、暂停、恢复 | **全都要求"是人"** | `tool-goal/src/index.ts:224 / 265 / 273` |
| 模型自己能发起的只有"完成"和"卡住" | 而且必须**目标编号、版本号、轮次三者精确匹配** | `authority.ts:77-83` |

**他们已经堵上的两个坑，值得原样抄走**：

**坑一：默认值的方向。** 给 agent 塞后续消息的接口（`followup()` / `steer()`）要求带一个"来源"；而**所有面向人的入口都把来源写死成"人"**（ACP、API 代理、SDK 服务端、无头模式）。于是**任何非人类的消息生产者，只要不显式声明自己是谁，就静默继承了人的权限**。`authority.ts:65-69` 那条注释就是在警告这件事：「An omitted `Agent.followup()` / `steer()` source resolves to `user`, so non-human producers must supply their own source rather than inheriting this authority.」

**坑二：合成消息的来源写死。** 目标自动续跑时合成的那条消息，来源在合成的那一行就写死成"目标"（`packages/goal/goal-round-driver/src/index.ts:177-179`：`source: { kind: 'goal', goalId, revision, round }`），**结构上不可能被误认成人说的**。

## 2.2 翻译成我们的形式

我们的 `actor` 是三段：`namespace:type:session`。**中间那段承担"人 / agent"的区分。**

**判据（三条全要，缺一不算）**：

一条要改动树的痕迹（`adopted` / `resumed` / `corrected` / `dropped` / `done` / `merged`）算数，当且仅当：

1. 它的**上一步直接指向**一条痕迹 H；
2. H 的 `actor` 中间那段是 `human`；
3. H 是**从人的门进来的**（第 2.3 节）。

**三条都在讲同一件事：这次改动必须挂在我说过的某一句话上，而那句话摆在那儿，我一看就知道是不是。**

**"直接指向"这一跳不能省。** 允许隔几层，就等于允许 agent 拿上周的一句话当今天的授权。DSH 用"当前这一轮"划这条界；我们没有"轮"，最近的等价物就是**一跳**。

**默认值反过来**：

> **中间那段不是 `human` 的，一律不算人。** 包括空的、拼错的、没写的、不认识的。

DSH 那边默认是"人"（因为他们的默认发生在人的门口，那儿是对的），代价是必须靠一条注释提醒每个别的生产者显式声明自己。**我们把默认反过来，那个坑在结构上就不存在了**——不是我们更小心，是这个错误没地方犯。

## 2.3 两道门：人的门 / agent 的门

判据的第 3 条要有东西兜着，否则 agent 只要自己写一条 `actor` 中间段是 `human` 的痕迹，判据就被绕过去了。

**做法照 DSH**：他们的模型够不着宿主入口（ACP / API 代理 / SDK 服务端），所以模型伪造不出一条"人说的话"。我们的对应物：

| | 谁能用 | 写得出什么 |
|---|---|---|
| **人的门** | 转录截获、CLI、面板 | **可以**写 `actor` 中间段为 `human` 的痕迹 |
| **agent 的门**（`trace.record`） | agent | **写不出**——中间段是 `human` 的当场被拒 |

**验**：拿 agent 的门去写一条"人说的话"，当场被拒，而且什么都没留下。

**这道门保不了什么，必须说清楚**（★4 / ★5，见缺口表）：门只能保证"这次改动挂在我的某一句话上"，**保不了"我真的是这个意思"**。DSH 有一模一样的残余——模型从人的一轮话里**自己判断**该建一个什么目标，判错了门也拦不住。

**补救不是加机制，是 U19**：它猜错了我看得见（第三节的记号）、一句话就能纠（第四节）、纠的留得下来。**这条残余风险恰好就是 U19 存在的理由**，所以不该在这里再造一层。

## 2.4 那 agent 到底能干什么

**能提，不能认。** `intent.proposed` 随便写，一条也不会长成节点。

**"完成"要不要给 agent 一个口子？** DSH 给了（模型能自己标完成/卡住，条件是目标编号+版本号+轮次精确匹配）。**我们不给**，理由是：

- 他们敢给，是因为**有轮次和版本号做精确匹配**——那个"当前这一轮"是硬边界。我们没有对应物，**为了开这个口子去造一个"轮"，就是为了给出口子而造机制**。
- 而且这正是最容易判错的地方：**任务干完了 ≠ 我的意图达成了。**

**代价**：很多节点永远不会被标成"做完了"，悬着的名单会长。**这个代价是需求接受的**——U16 明说"没走完不等于没用""不需要有人催我收尾"。

**便宜的替代**：agent 可以**提议**"这条我看着像做完了"（就是一条 `intent.proposed`），我一句话就认。零新机制；而**我不吭声就是还悬着**——那本身就是 U19 ④ 要的那种信号。

# 三、agent 提了我没接（U19 ④）

需求说得很硬：**那不是树上的洞，是关于 agent 的信号**，三种可能——上下文没给够、没讲清楚、这事本来不重要——**三种都是 agent 该改的地方**。

## 3.1 不需要新机制：它已经在痕迹里了

`intent.proposed` 本身就是留下来的那份东西：有时间、有是哪个 agent 提的、有提了什么。**没有第二个地方要写，也没有谁要记得多敲一条命令**（这是 U12 已经解决的事）。

## 3.2 "没接"是一次查询

**不设"待回应"这种状态。** 状态要有人去改，就会忘改；查询不会。

> 一条提议**有没有被回应**，看它后面有没有一条痕迹拿它当上一步或当依据。这跟 [`trace.md`](./trace.md) 第二节往前走的那个查询是同一个查询（`became()`），**一行新代码都不用写**。

**什么时候算"没接"，判据要可计算，而且不许冤枉人**：

| 情况 | 算什么 |
|---|---|
| 这条提议之后，我**还没再开口** | **还没轮到**，不是没接 |
| 我开口了，而那次开口**没有回应它** | **没接**——从这一刻起它进信号那一堆 |

**为什么用"我的下一次开口"当界**：因为它完全落在痕迹上，不需要计时器，也不会因为我今天忙就冤枉 agent 一次。这跟 DSH 用"当前这一轮"划界是同一个想法——**用对话本身的节拍当边界，不用墙上的钟。**

> [`acceptance/trace.md`](../acceptance/trace.md) 最后那段讲过："一条会冤枉人的检验，用起来和一条不会说'不'的检验一样坏。" 计时器就是那种会冤枉人的做法。

## 3.3 记号给机器，颜色给眼睛——两件事分开做

需求最后一句写得很明确：「颜色是给眼睛的——看不见我就不会纠；某种固定的记号是给机器的——留在记录里、将来从一堆对话里能捞出来的，是记号不是颜色。」

**所以是两条要求，分开满足**：

**给眼睛**：注入到 agent 上下文、以及回复里出现的那段"你在追什么"，**认了的和猜的必须分开写**，在终端里长得不一样。看不见哪句是猜的，我就不会开口纠。

**给机器**：那段文字里带一个**固定的行首记号**，纯文本状态下一条正则就能捞：

```
[意图·认了] project_theseus > 换地基 > 写需求 > 意图树
[意图·猜的] 你接下来大概是想把验收也写了？
[意图·纠了] 不是验收，是先把判据定下来
```

**为什么这样就能捞得出来**：因为对话已经被自动截走了（[`trace.md`](./trace.md) 第六节第二类，不靠谁记得）。**记号之所以有用，是它搭在一条已经在跑的管子上**，不用另铺一条。

**三条要求，字符串本身可以换**：① 纯文本下一条正则捞得出；② 终端里三者分得清；③ 被回应之后，**回应本身也带记号**（否则捞出来只有猜，没有纠，成不了对）。

★2：**这三个字符串是我们定的**，没有别人的先例。得实测：拿 15G 旧对话跑一遍，看会不会撞上已有的文本。

# 四、我出言修正时怎么进系统（U19）

## 4.1 修正也是痕迹，树跟着变，历史不改

我说"不是这个意思，是 X"，落成一条 `intent.corrected`：上一步指向我说的那句话，依据指向它刚才猜的那条。

- **树跟着变**：折叠读到它，就把那个节点的**现在的说法**换掉。
- **历史不改**：旧说法一个字没动，还在原来那条 `intent.adopted`（或 `intent.proposed`）里。

**于是"它猜错了什么、我改成了什么"天然成对留下来**——那正是 U19 ③ 要的原料，不用另外攒一份。

**谁的做法**：追加不修改，是账本的老规矩；`trace` 那张表本来就只追加。**这里没有新东西，是把已有的性质用上。**

## 4.2 一句话就能纠：我不给编号

**人不会去查节点号。** 我只说那句话，写痕迹的是 agent——它知道自己刚才猜的是哪条，让它自己指。

**谁指的是 agent，做数的是我那句话。** 同一道判据（第二节），不另开口子。

**指错了会怎样**：它把修正挂到了别的节点上。**这仍然是看得见的**——下次它讲"我在追什么"就讲错了，我再纠一次。**代价一句话，而且第二次纠正本身又是一条原料。**

## 4.3 "我不要了"只有一种写法

`intent.dropped` 一种类型管两件事：

- 被指的是一条**提议** → "这条我不要"
- 被指的是一个**节点** → "这件事我不做了"

**从被指的那条是什么，就看得出是哪种**，不需要两个名字。

**必须带一句为什么。** 这条是从 DSH 借的：他们对否掉的提案有一条硬规矩——**只在"它的理由仍能避免一种诱人且影响重大的错误"时保留**。要用这条判据，理由就得先在那儿。**放弃的理由是将来"要不要捡回来"的唯一依据。**

## 4.4 没有"悄悄消失"这个状态

**这一条整条照抄 DSH**（`.agents/notes/README.md`）：过时的提案要**转成"否掉"**，绝不允许悄悄归档。他们的实测计数（英文正文，中文副本不重复计）：**在提 25 / 落地 506 / 否掉 11 / 归档 142**。

落到我们这儿：

> 一条开过头的意图，只可能在三种里——**还悬着 / 我说了不做 / 做完了**。**没有第四种。**

**为什么这条值钱**：0.1 节量出来的那件事——旧系统那份"防丢视图"漏了至少 15 条——就是第四种状态在起作用：**它既没被标记，也没在名单上，就那么没了。**

# 五、融合（U18）

**`intent.merged` 加的是一条非出生边，两条出生边一个字不改。**

- 树还是树：每个节点仍然只有一个"它从哪儿分出来的"，**U15 那条"永远只有一条路"仍然成立**。
- 两边各自从哪儿来仍然查得到——**这就是需求那句"不是把其中一条抹掉"**。
- 融合之后当前落在哪：**不动**（还是我说这句话时正在追的那个）。另一条节点从此在显示时带上"已与 X 并"。

**这一处没有现成做法可抄。** DSH 每个会话只有一个当前目标，没有父子，更没有"两个目标是一件事"——**在那儿找不到血缘建模的先例。** ★3。

**真发生过的那件事**（需求里写着）：道路管养的本子和 LLMAD 那份研究，最后是一份研究出两个本子、共用同一个内核。**要是并的时候把"它俩本来是分开的"丢了，将来就说不清为什么这份研究要同时对两个方向负责。**

# 六、一句话，和跳走了能回来（U15 / U17）

## 6.1 一句话 = 沿出生边走到根

从当前节点顺着出生边往上走，走到根，连起来就是那句话。**这正是项目规矩里手写的那条路径**——`意图树路径：<project> -> <根意图> -> … -> <当前>`。

**那条规矩是这个需求的手工版**（需求 U15 原话）。现在它是查出来的：不用谁记得写，也不会写错。

## 6.2 摆在那儿，不用我要

新会话开场，把这句话直接放到 agent 面前。**照搬 [`trace.md`](./trace.md) 第八节已经定下的做法**（Claude Code 每次开场注入 `MEMORY.md`）——**同一条管子，多送一样东西，没有新机制。**

★8：**路径深了之后"一句话"会变长。** 旧那棵最深四层，一句话还成；十层会怎样没定。

## 6.3 回来：不用记编号，不用手写交接

- **跳走**：当前移到别处，那次移动本身是一条痕迹。
- **回来**：`intent.resumed`，当前移回去。
- **"接着刚才那儿走"要的不只是节点，还有当时的上下文**——那就是挂在这个节点下面的那些痕迹。**查法是现成的**：以这个节点为起点往前走（`became()`），拿到它名下发生过的事。

**为什么这条要紧**：现在的办法是**人手写一份交接文件，还得记住一串会话编号**（`handoff-20260611-session-3cc78184`）。**一件事需要人手写交接才能接上，说明这个系统没在替你记着。**

# 七、悬着的分支（U16）

## 7.1 定义

**一个节点是"悬着的"，当且仅当它既没被标成"做完了"，也没被标成"我不做了"。** 就这一条，没有别的条件。

**特意不加的三个条件**：不看它多久没动、不看它在第几层、不看名单有多长。

**这条判据是从 DSH 抄的**：他们的归档指引明写着**不要根据字数、存续时间或目标配额来判断**。而它同时也是需求自己的立场——需求里明确删掉了 VISION 那句"分叉走远时主动提醒回归"，理由是「不要」，而且「"远"本来也没定义清楚（层数深？时间久？还是跟根意图的关系淡了？）」。

**两边独立得出同一个结论**，所以这一条定得比较硬。

## 7.2 不催

**跑多久都不出现催收尾的提示。** 需求删掉的那条不许悄悄长回来。

## 7.3 名单怎么排

**按最近一次有动静的时间倒序。** 这不是"催你收尾"的判据，只是"最近碰过的更容易接上"。**排序不改变任何一条的去留。**

★6：**名单会长到什么程度没实测。** 旧那棵里非闭环的有 109 条；因为不给 agent 标"做完了"的口子（2.4 节），新的只会更长。**长到什么程度还算能用，得跑起来看。**

# 八、DSH 那套目录状态机：哪些拿得过来，哪些不适用

DeepSeek Harness 用**目录状态机**管设计笔记：状态编码在路径里（`proposed/` `implemented/` `rejected/` `archived/`），笔记随状态在目录间移动，门禁交叉检查文件里那行 `Status:` 和它所在的目录是否一致——**说谎在机械上做不到**。

**这套东西对 U16「分支不会丢、捡得回来」是现成答案吗？部分是。逐条说。**

## 拿得过来的三条

| 他们的做法 | 我们怎么用 | 为什么成立 |
|---|---|---|
| **绝不归档"在提"的；过时的提案要转成"否掉"** | 4.4 节：**没有第四种状态** | 0.1 量出来的那 15 条漏网，就是第四种状态干的 |
| **归档判据不看字数、存续时间、目标配额** | 7.1 节：悬着的判据只有一条 | 和需求删掉"主动提醒回归"那条撞上了同一个结论 |
| **否掉的要保留理由**（"它的理由仍能避免一种诱人且影响重大的错误"） | 4.3 节：放弃必须带一句为什么 | 那句话是将来"要不要捡回来"的唯一依据 |

## 不适用的四条——**这部分比上面那部分重要**

**① 门禁交叉检查（状态写两处、互相核对）：在我们这儿没有对应物。**

他们需要这道门禁，**是因为状态存在两个地方**——目录一份、文件里的 `Status:` 行一份。两处会不一致，所以要一道门禁去比。

我们的状态**只存在一个地方**（痕迹），树是折叠出来的，**没有第二份可以拿来对**。所以这道门禁**不是我们没做，是那个问题不存在**。

> 这跟 [`PRINCIPLES.md`](../PRINCIPLES.md) 里那条更硬的观察是同一回事：**成熟做法给的不只是省工，而是让一批需求直接不存在了；而自己造的方案要解决的难题，很多是方案自己带来的。** 这里反过来看也成立——**他们那道门禁要解决的难题，是"状态存两份"这个选择自己带来的。我们没做那个选择。**

**② "删干净"这个动作：不适用。**

他们删掉不再有用的否掉笔记，是为了控制一棵**靠人翻**的目录树的规模。我们不删——**删掉一条被别人当上一步指着的痕迹，就制造了一条断链，那正是 U7 最怕的东西**（[`trace.md`](./trace.md) 第五节已经为这件事定过：降采样不删除）。

**判据本身可以留下来当筛子**（捡的时候先看"这条理由还能不能拦住一个诱人的错误"），**但"删"这个动作不能抄。**

**③ 笔记格式（问题 / 决策 / 备选方案 / 影响）套到节点上：不适用。**

他们的一份笔记是一份文档，四段格式撑得住。**我们的一个节点是一句话**——"我在追什么"。要求每个节点写四段，会当场把 U19 那条「我一句话就能纠」压死。

**这套格式该用在哪儿：用在这份设计文档上。** 本文第 1.4 节那个"备选方案，以及为什么放弃"就是照它写的——**记下考虑过又放弃的路，是为了防止将来重新吵一遍。**

**④ 目标那套东西本身：在血缘上没有先例可抄。**

DSH 的目标**每个会话只有一个当前值**，没有父子、没有出生边；"计划"是一个布尔开关（`plan/mode: { active: boolean }`）；待办是平铺数组、每次整表替换（`tool-todo`：'Send the ENTIRE list every call — it REPLACES the previous list'）。

**所以第一节（出生边）和第五节（融合）是这份设计里必须自己造的两处。**

# 九、这一份设计里，哪些是别人的，哪些是自己造的

> **这张表是 [`PRINCIPLES.md`](../PRINCIPLES.md) 那条原则的落账。**

**用别人成熟做法的：**

| 用在哪 | 用了谁的 |
|---|---|
| **"是不是我的意图"是一次查询，不是一个字段** | **DSH 的 `direct-human`**（`tool-goal/src/authority.ts`） |
| **默认值不能是"人"；非人类生产者必须显式声明自己** | **DSH 已经踩过并注释出来的那个坑**（`authority.ts:67-68`）——我们把默认反过来 |
| **合成的东西来源写死，结构上不可能被误认成人说的** | **DSH 的目标续跑**（`goal-round-driver/src/index.ts:177-179`） |
| **模型够不着人的入口** | **DSH 的宿主入口 / 模型工具之分**，我们叫人的门 / agent 的门 |
| **折叠成当前状态，十几行** | **DSH 的 `applyGoalProjection`**（`goal/src/index.ts:96-113`） |
| **一个当前值，按谁取由范围定** | **DSH 的 `ctx.goals.get(agent)`**（他们按会话，我们按人） |
| **没有"悄悄消失"这个状态** | **DSH 的 Agent Note 生命周期** |
| **收不收不看时长、深度、数量** | **DSH 的归档指引** |
| **放弃要留理由，理由用"还能不能拦住一个诱人的错误"来筛** | **DSH 对否掉笔记的规矩** |
| **备选方案逐条记下来** | **DSH 的 Agent Note 格式**（用在这份文档上，不用在节点上） |
| **节点就是那条痕迹，不另给号** | **git 的 commit** |
| **追加不修改，旧说法原地不动** | **账本；`trace` 那张表本来就是这样** |
| **开场把一份东西直接放到 agent 面前** | **Claude Code 注入 `MEMORY.md`**（[`trace.md`](./trace.md) 第八节已定） |
| **往前走的那个查询（有没有被回应）** | **[`trace.md`](./trace.md) 第二节的 `became()`，一行新代码都不写** |

**★ 自己造的，只有四处**，每一处都值得被单独盯着：

| ★ | 自己造的 | 为什么没有现成的 |
|---|---|---|
| **★A** | **出生边 = 出生那一刻的当前**（不给显式的父亲字段） | DSH 的目标没有父子，没得抄。这一处最划算：**删掉一个字段的同时满足了 U17**——要挂到老节点上就得先"回去"，而"回去"正是要留痕的 |
| **★B** | **融合 = 一条非出生边，两条出生边不动** | 同上，没有先例。它是 U18 唯一的落点 |
| **★C** | **"没接"的边界 = 我的下一次开口** | 形状是从 DSH 的"当前这一轮"借的，但**具体划在哪儿是我们定的**——我们没有"轮" |
| **★D** | **那三个记号字符串**（`[意图·认了]` / `[意图·猜的]` / `[意图·纠了]`） | 需求要一个"留在记录里、将来捞得出来"的记号，具体长什么样没人能替我们定 |

**四处都很小，而且都可验证。** 除此之外这份设计里没有一处是新发明的。
